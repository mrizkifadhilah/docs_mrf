# Sourcerer (Bajracharya et al., 2009)

*Sistem ini mengimplementasikan infrastruktur repositori perangkat lunak skala masif yang mengekstraksi metadata struktural dari kode sumber untuk mendukung kueri berbasis relasi entitas dan analisis program statis.*

**Judul**
Sourcerer: An internet-scale software repository, 2009 ICSE Workshop on Search-Driven Development - Users, Infrastructure, Tools and Evaluation (SUITE 2009), IEEE Computer Society, 2009

**Penulis**
Sushil Krishna Bajracharya, Joel Ossher, Cristina Videira Lopes (University of California, Irvine, Amerika Serikat)

**Inti Paper**
Paper ini memperkenalkan **Sourcerer**, sebuah infrastruktur besar yang dirancang untuk mengindeks dan menganalisis kode sumber terbuka (*open source*) dari internet dalam skala yang sangat luas. Masalah yang ingin dipecahkan adalah mesin pencari kode yang ada saat itu (seperti Google Code Search generasi awal) hanya mencari kode berdasarkan teks saja, mirip mencari dokumen biasa. Padahal, kode memiliki "struktur" (seperti hubungan antar kelas, fungsi, dan variabel) yang sangat kaya. Sourcerer dibangun untuk menangkap informasi struktural tersebut agar alat pencari kode lainnya bisa dibangun dengan lebih canggih, lebih akurat, dan mampu memahami hubungan logika di dalam kode, bukan sekadar mencocokkan kata.



**Bedah Abstrak Mendetail**
1. **"Vast quantities of open source code are now available online, presenting a great potential resource for software developers."**
   - *Maksud:* Saat ini tersedia sangat banyak kode sumber terbuka di internet yang bisa menjadi sumber daya sangat berharga bagi pengembang perangkat lunak.
2. **"Yet the current generation of open source code search engines fail to take advantage of the rich structural information contained in the code they index."**
   - *Maksud:* Namun, mesin pencari kode yang ada sekarang gagal memanfaatkan informasi struktur (seperti hubungan antar komponen kode) yang sebenarnya tersedia di dalam kode yang mereka simpan.
3. **"We have developed Sourcerer, an infrastructure for large-scale indexing and analysis of open source code."**
   - *Maksud:* Peneliti telah mengembangkan Sourcerer, sebuah infrastruktur untuk menyimpan indeks dan menganalisis kode sumber terbuka dalam skala besar.
4. **"By taking full advantage of this structural information, Sourcerer provides a foundation upon which state of the art search engines and related tools easily be built."**
   - *Maksud:* Dengan memanfaatkan informasi struktur secara maksimal, Sourcerer menjadi fondasi dasar agar mesin pencari kode tercanggih dan alat terkait lainnya bisa dibuat dengan mudah.
5. **"We describe the Sourcerer infrastructure, present the applications that we have built on top of it, and discuss how existing tools could benefit from using Sourcerer."**
   - *Maksud:* Peneliti menjelaskan bagaimana cara kerja infrastruktur Sourcerer, menunjukkan aplikasi apa saja yang sudah mereka buat di atasnya, dan mendiskusikan bagaimana alat-alat yang sudah ada bisa menjadi lebih baik jika menggunakan Sourcerer.

**Baseline**
* **Google Code Search (Google, 2006):** Digunakan sebagai baseline mesin pencari kode berbasis teks murni (Information Retrieval tradisional) untuk menunjukkan keunggulan pencarian berbasis struktur.
* **Koders & Krugle (Koders/Krugle, 2010):** Digunakan sebagai baseline sistem komersial yang saat itu masih mengandalkan indeks leksikal/teks untuk pencarian kode terbuka di web.
* **Strathcona (Holmes & Murphy, 2005):** Digunakan sebagai baseline alat pemberi rekomendasi kode yang menggunakan konteks struktural untuk menyarankan contoh penggunaan API.
* **Code Conjurer (Hummel et al., 2008):** Digunakan sebagai baseline sistem pencarian kode berbasis komponen yang dapat diintegrasikan langsung ke dalam IDE.

**Keyword**
Open-source code, Structural information, Code search engine, Software repository, Information retrieval.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Penting sebagai Referensi Infrastruktur).**
Paper ini wajib masuk ke riset Anda karena Sourcerer adalah salah satu infrastruktur pencarian kode paling berpengaruh di dunia akademik. Jika riset Anda membahas tentang **pencarian kode berbasis struktur** (*structure-based code search*), paper ini memberikan penjelasan mendalam tentang bagaimana data kode harus disimpan dan dikelola (parsing dan metadata) agar pencarian tidak hanya bergantung pada kata kunci teks.

**Perbedaan dengan Paper Sebelumnya**
1. **Fokus Kontribusi:** Berbeda dengan paper **Sourcerer (Linstead et al., 2009)** yang fokus pada algoritma *CodeRank* dan *Topic Modeling*, paper versi SUITE ini lebih fokus pada **arsitektur infrastruktur repositori** dan layanannya bagi alat lain.
2. **Integrasi:** Jika paper **CodeGenie (2009)** fokus pada pengujian kode, paper ini fokus pada penyediaan **basis data terstruktur** yang memungkinkan CodeGenie tersebut bekerja.
3. **Skalabilitas:** Dibandingkan dengan **SNIFF (2009)** yang lebih ke arah kueri pengguna, Sourcerer fokus pada **penanganan data skala internet** (miliaran baris kode) agar bisa diolah secara efisien.
