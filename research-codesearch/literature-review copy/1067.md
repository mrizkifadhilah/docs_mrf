# API-OntoSearch (Alnusair et al., 2010)

*Penelitian ini mengintegrasikan representasi ontologi kode sumber dengan teknik points-to analysis untuk mengekstraksi ketergantungan tipe data secara presisi guna menghasilkan rekomendasi cuplikan kode semantik dalam skenario minim artefak referensi.*

**Judul**
Effective API navigation and reuse, 11th IEEE International Conference on Information Reuse and Integration (IRI 2010), IEEE, 2010

**Penulis**
Awny Alnusair, Tian Zhao, Eric Bodden (University of Wisconsin-Milwaukee & Technische Universität Darmstadt)

**Inti Paper**
Paper ini membahas cara membantu pemrogram menemukan contoh kode yang tepat saat menggunakan perpustakaan (*library*) baru yang dokumentasinya kurang lengkap. Masalahnya, banyak sistem pencari kode membutuhkan basis data contoh yang sudah ada, padahal banyak library tidak memilikinya. Peneliti menciptakan sebuah sistem yang menggunakan **Ontologi** (sebuah peta digital yang memetakan hubungan antar konsep kode) dan teknik **Points-to Analysis** (cara komputer melacak hubungan antar variabel dan tipe data secara mendalam). Dengan metode ini, sistem bisa memahami struktur library tersebut secara mandiri dan memberikan rekomendasi cuplikan kode yang akurat kepada pemrogram, bahkan tanpa memerlukan kumpulan contoh kode manual sebelumnya.



**Bedah Abstrak Mendetail**
1. **"Most reuse libraries come with few source-code examples that demonstrate how the library at hand should be used."**
   - *Maksud:* Kebanyakan perpustakaan kode yang bisa dipakai ulang hanya menyertakan sedikit contoh kode asli yang menunjukkan cara pemakaiannya.
2. **"We have developed a source-code recommendation approach for constructing and delivering relevant code snippets that programmers can use to complete a certain programming task."**
   - *Maksud:* Peneliti telah mengembangkan sebuah cara rekomendasi kode untuk menyusun dan memberikan cuplikan kode yang relevan agar bisa dipakai pemrogram menyelesaikan tugasnya.
3. **"Our approach is semantic-based; relying on an explicit ontological representation of source-code."**
   - *Maksud:* Pendekatan ini berbasis semantik (makna), yang mengandalkan representasi ontologi (peta hubungan konsep) yang jelas dari kode sumber.
4. **"We argue that such representation opens new doors for an improved recommendation mechanism that ensures relevancy and accuracy."**
   - *Maksud:* Peneliti berpendapat bahwa model ontologi ini membuka peluang baru untuk sistem rekomendasi yang menjamin ketepatan dan keakuratan hasil.
5. **"Current recommendation systems require an existing repository of relevant code samples. However, for many libraries, such a repository does not exist."**
   - *Maksud:* Sistem rekomendasi saat ini biasanya butuh gudang data yang sudah penuh dengan contoh kode, padahal banyak library yang tidak memilikinya.
6. **"Therefore, we instead utilize points-to analysis to infer precise type information of library components."**
   - *Maksud:* Sebagai gantinya, peneliti menggunakan teknik *points-to analysis* untuk menebak informasi tipe data yang akurat dari komponen-komponen library tersebut.
7. **"We have backed our approach with a tool that has been tested on multiple libraries. The obtained results are promising and demonstrate the effectiveness of our approach."**
   - *Maksud:* Cara ini sudah diwujudkan dalam sebuah alat yang diuji pada banyak library, dan hasilnya sangat bagus serta membuktikan efektivitas metode tersebut.

**Baseline**
* **Strathcona (Holmes & Murphy, 2005):** Digunakan sebagai baseline untuk sistem rekomendasi kode yang mengandalkan konteks struktural (pencocokan struktur kode lokal) untuk mencari contoh di repositori.
* **Jungloid Mining (Mandelin et al., 2005):** Digunakan sebagai baseline teknik penambangan urutan pemanggilan API untuk membantu pemrogram menavigasi library yang kompleks.
* **Michail’s Library Reuse Patterns (Michail, 2000):** Digunakan sebagai baseline untuk teknik data mining yang mengekstraksi pola penggunaan library menggunakan aturan asosiasi.
* **JIRiSS (Poshyvanyk et al., 2006):** Digunakan sebagai baseline alat eksplorasi kode sumber (plugin Eclipse) untuk membandingkan kemampuan navigasi antar komponen library.

**Keyword**
Code reuse, Ontology, Points-to analysis, Semantic recommendation, API navigation.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Cold-Start Problem).**
Paper ini sangat relevan jika riset Anda membahas tantangan **"Cold-Start"** dalam Code Search (mencari kode saat contoh referensi di repositori sangat terbatas). Penggunaan **Ontologi** dan **Points-to Analysis** memberikan perspektif teknis yang kuat tentang bagaimana mesin pencari bisa memahami "maksud" sebuah library hanya dari kodenya sendiri tanpa bergantung pada metadata teks atau dokumentasi luar. Ini adalah rujukan kunci untuk riset *Semantic Code Search* yang berbasis pada hubungan antar entitas kode.

**Perbedaan dengan Paper Sebelumnya**
1. **Ketersediaan Data:** Berbeda dengan paper **Sourcerer (2009)** yang membutuhkan repositori skala internet yang besar, paper ini dirancang untuk bekerja pada library individu yang memiliki **sedikit contoh kode**.
2. **Representasi Pengetahuan:** Jika paper **Context-NL (2009)** menggunakan hierarki kata kunci bahasa alami, paper ini menggunakan **Ontologi Formal** untuk memetakan hubungan logika antar komponen kode.
3. **Kedalaman Analisis:** Dibandingkan dengan **MAPO (2009)** yang fokus pada pola frekuensi penggunaan, paper ini melakukan analisis **Points-to** yang jauh lebih mendalam secara teknis untuk memastikan akurasi tipe data yang direkomendasikan.
