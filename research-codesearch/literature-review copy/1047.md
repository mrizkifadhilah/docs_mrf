# MAPO (Zhong et al., 2009)

*Penelitian ini mengusulkan kerangka kerja penambangan sekuensial pada repositori kode sumber terbuka untuk mengekstraksi pola penggunaan API (usage patterns) berdasarkan frekuensi pemanggilan metode dan aturan urutan operasional guna mengoptimasi hasil temu kembali pada mesin pencari kode.*

**Judul**
MAPO: mining and recommending api usage patterns, 23rd European Conference on Object-Oriented Programming (ECOOP 2009), Springer, 2009

**Penulis**
Hao Zhong, Tao Xie, Lu Zhang, Jian Pei, Hong Mei (Peking University, China; NC State University, USA; Simon Fraser University, Canada)

**Inti Paper**
Paper ini memperkenalkan **MAPO**, sebuah sistem cerdas yang membantu pemrogram memahami cara menggunakan *library* atau *framework* yang rumit. Masalah utama yang diangkat adalah ketika pemrogram menggunakan mesin pencari kode biasa, mereka sering mendapatkan hasil yang terlalu banyak (ribuan cuplikan kode), sehingga sulit menemukan contoh yang benar-benar berguna. MAPO bekerja dengan cara "menambang" repositori kode untuk menemukan **pola penggunaan API**. Pola ini memberi tahu pemrogram urutan perintah mana yang biasanya dipakai bersamaan dalam skenario tertentu. Selain hanya mencari, MAPO juga merekomendasikan cuplikan kode yang paling relevan berdasarkan pola tersebut. Hasil pengujian menunjukkan bahwa pengembang yang menggunakan MAPO menghasilkan kode dengan kesalahan (*bug*) yang lebih sedikit dibandingkan mereka yang hanya menggunakan alat pencari kode standar.



**Bedah Abstrak Mendetail**
1. **"To improve software productivity, when constructing new software systems, programmers often reuse existing libraries or frameworks by invoking methods provided in their APIs."**
   - *Maksud:* Untuk meningkatkan produktivitas, pemrogram biasanya menggunakan kembali perpustakaan atau kerangka kerja yang sudah ada dengan memanggil fungsi-fungsi (API) yang tersedia.
2. **"Those API methods, however, are often complex and not well documented."**
   - *Maksud:* Sayangnya, cara pakai fungsi-fungsi tersebut sering kali rumit dan tidak dijelaskan dengan baik di buku panduan.
3. **"To get familiar with how those API methods are used, programmers often exploit a source code search tool to search for code snippets that use the API methods of interest."**
   - *Maksud:* Agar paham cara pakainya, pemrogram biasanya menggunakan alat pencari kode untuk melihat contoh nyata dari orang lain.
4. **"However, the returned code snippets are often large in number, and the huge number of snippets places a barrier for programmers to locate useful ones."**
   - *Maksud:* Masalahnya, hasil pencarian sering kali berjumlah ribuan, sehingga pemrogram kewalahan memilih mana yang benar-benar bermanfaat.
5. **"In order to help programmers overcome this barrier, we have developed an API usage mining framework and its supporting tool called MAPO... for mining API usage patterns automatically."**
   - *Maksud:* Untuk mengatasi hal ini, peneliti membuat sistem MAPO yang secara otomatis menambang dan meringkas pola-pola penting dalam penggunaan kode tersebut.
6. **"A mined pattern describes that in a certain usage scenario, some API methods are frequently called together and their usages follow some sequential rules."**
   - *Maksud:* Pola yang ditemukan menjelaskan bahwa dalam situasi tertentu, beberapa fungsi biasanya dipanggil bersamaan dalam urutan yang pasti.
7. **"MAPO further recommends the mined API usage patterns and their associated code snippets upon programmers' requests."**
   - *Maksud:* MAPO kemudian menyarankan pola-pola ini dan cuplikan kodenya langsung kepada pemrogram saat dibutuhkan.
8. **"Our experimental results show that with these patterns MAPO helps programmers locate useful code snippets more effectively than two state-of-the-art code search tools."**
   - *Maksud:* Hasil eksperimen membuktikan MAPO lebih efektif membantu mencari kode dibanding dua alat pencari kode tercanggih saat itu.
9. **"The results show that using MAPO, programmers produce code with fewer bugs when facing relatively complex API usages, comparing with using the two state-of-the-art code search tools."**
   - *Maksud:* Hasil akhir menunjukkan pemrogram yang memakai MAPO membuat lebih sedikit kesalahan saat menangani kode yang rumit.

**Baseline**
* **Prospector (Mandelin et al., 2005):** Digunakan sebagai baseline sistem pencari kode yang mensintesis jalur panggilan API berdasarkan tipe input dan output.
* **Strathcona (Holmes & Murphy, 2005):** Digunakan sebagai baseline alat pemberi rekomendasi kode yang menggunakan struktur konteks di sekitar kode yang sedang diketik.
* **Agrawal (Agrawal & Srikant, 1995):** Digunakan sebagai baseline algoritma penambangan pola sekuensial (*sequential pattern mining*) tradisional yang menjadi fondasi teknik penambangan di MAPO.
* **Ammons (Ammons et al., 2002):** Digunakan sebagai baseline untuk teknik penambangan spesifikasi protokol API dari eksekusi program.

**Keyword**
Code search, API usage mining, Usage patterns, Sequential rules, Open source repositories.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah referensi fundamental untuk topik **API-oriented Code Search**. Jika riset Anda berfokus pada bagaimana mesin pencari kode seharusnya tidak hanya memberikan "teks", tetapi memberikan "pengetahuan" tentang bagaimana API seharusnya dipanggil secara berurutan, maka MAPO adalah rujukan utamanya. Paper ini membuktikan bahwa ringkasan pola jauh lebih berharga bagi pengembang daripada ribuan baris kode mentah hasil pencarian.

**Perbedaan dengan Paper Sebelumnya**
1. **Penyajian Hasil:** Berbeda dengan paper **Sourcerer (2009)** yang memberikan daftar file, MAPO memberikan **pola (pattern)** dan mengelompokkan hasil pencarian berdasarkan kemiripan cara pakai.
2. **Kualitas Kode:** Jika paper **SNIFF (2009)** fokus pada kemudahan kueri bahasa alami, MAPO lebih fokus pada **kualitas hasil** (mengurangi *bug*) dengan memberikan contoh yang sudah tervalidasi oleh pola umum di repositori.
3. **Automasi Penambangan:** Dibandingkan dengan **SpotWeb (2008)** yang fokus pada popularitas (hotspots), MAPO lebih mendalam dengan mengekstraksi **aturan sekuensial** (urutan langkah 1, 2, 3) dalam menggunakan API.
