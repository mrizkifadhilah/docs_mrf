# CSE Framework (Thummalapenta, 2007)

*Framework ini mengoptimasi utilitas Code Search Engines (CSE) melalui mekanisme filtrasi dan augmentasi terhadap cuplikan kode parsial guna memfasilitasi identifikasi hotspot dan deteksi defek pada repositori kode sumber skala masif.*

**Judul**
Exploiting code search engines to improve programmer productivity, 22nd International Conference on Object-Oriented Programming Systems, Languages, and Applications (OOPSLA 2007), ACM, 2007

**Penulis**
Suresh Thummalapenta (North Carolina State University, Amerika Serikat)

**Inti Paper**
Paper ini membahas cara memanfaatkan mesin pencari kode (*Code Search Engine* atau CSE) untuk membantu pemrogram bekerja lebih cepat. CSE sangat hebat karena bisa mencari di antara miliaran baris kode di internet, namun hasilnya seringkali terlalu banyak dan kodenya tidak lengkap (hanya potongan/parsial). Peneliti mengusulkan sebuah kerangka kerja (*framework*) untuk mengatasi masalah tersebut. Kerangka kerja ini membantu menyaring hasil pencarian agar hanya menampilkan contoh kode yang paling relevan, menemukan bagian kode yang paling sering digunakan (*hotspots*), hingga menemukan bug. Peneliti membuktikan efektivitas ide ini dengan membuat dua alat bantu berdasarkan kerangka kerja tersebut.



**Bedah Abstrak Mendetail**
1. **"Code Search Engines (CSE) can serve as powerful resources of open source code, as they can search in billions of lines of open source code available on the web."**
   - *Maksud:* Mesin pencari kode adalah sumber daya yang luar biasa bagi pengembang karena mampu memindai miliaran baris kode sumber terbuka yang tersebar di internet.
2. **"The strength of CSEs can be used for several tasks like searching relevant code samples, identifying hotspots, and finding bugs."**
   - *Maksud:* Kekuatan mesin pencari ini bisa digunakan untuk berbagai tugas, seperti mencari contoh kode yang pas, melihat bagian mana yang populer digunakan, hingga mendeteksi kesalahan program.
3. **"However, the major limitations in using CSEs for these tasks are that the returned samples are too many and they are often partial."**
   - *Maksud:* Sayangnya, kelemahan utamanya adalah hasil yang diberikan mesin pencari terlalu menumpuk (jumlahnya ribuan) dan seringkali kodenya terpotong atau tidak utuh.
4. **"Our framework addresses the preceding limitations and thereby helps in using CSEs for these tasks."**
   - *Maksud:* Kerangka kerja yang diusulkan peneliti ini bertujuan untuk mengatasi masalah jumlah hasil yang berlebihan dan kode yang tidak utuh tersebut.
5. **"We showed the effectiveness of our framework with two tools developed based on our framework."**
   - *Maksud:* Peneliti mendemonstrasikan bahwa ide mereka berhasil melalui dua aplikasi nyata yang dibangun di atas kerangka kerja tersebut.

**Baseline**
* **Holmes (Holmes & Murphy, 2005):** Digunakan sebagai baseline untuk sistem rekomendasi contoh kode sumber yang memanfaatkan konteks struktural dari IDE pengguna.
* **Jungloid Mining (Mandelin et al., 2005):** Digunakan sebagai baseline untuk metode navigasi dan pencarian penggunaan API yang kompleks melalui teknik *mining*.
* **XSnippet (Sahavechaphan & Claypool, 2006):** Digunakan sebagai baseline untuk teknik penambangan cuplikan kode (*snippet*) yang relevan berdasarkan kueri pengguna di dalam repositori kode.

**Keyword**
Code search engine, Code examples, Code reuse, Programmer productivity, Hotspots.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah referensi wajib bagi riset Anda karena secara langsung membahas **limitasi dari mesin pencari kode (CSE)** dan bagaimana cara mengoptimalkannya. Thummalapenta adalah peneliti terkemuka di bidang ini (terkenal dengan alat PARSEWeb nantinya). Jika riset Anda bertujuan untuk "memperbaiki" hasil pencarian atau membuat sistem rekomendasi kode yang lebih cerdas, paper ini memberikan fondasi tentang masalah ketersediaan data parsial yang sering ditemui pada CSE.

**Perbedaan dengan Paper Sebelumnya**
1. **Fokus pada Output:** Berbeda dengan paper **Sourcerer (2006)** yang membangun infrastruktur pencarian, paper ini berfokus pada **bagaimana mengolah hasil** yang keluar dari infrastruktur tersebut agar berguna bagi produktivitas.
2. **Penanganan Masalah:** Jika paper **SemmleCode (2007)** melakukan pencarian semantik pada kode internal proyek sendiri, paper ini melakukan pencarian pada **miliaran baris kode eksternal (internet)** yang bersifat tidak terstruktur.
3. **Integrasi:** Dibandingkan dengan **CodeGenie (2007)** yang mengharuskan pembuatan *test case*, paper ini lebih fleksibel dalam mencari contoh penggunaan (*usage patterns*) dan *hotspots* tanpa ketergantungan penuh pada unit testing.
