# CodeGenie (Lemos et al., 2007)

*Sistem ini mengintegrasikan metodologi Test-Driven Development (TDD) dengan infrastruktur temu kembali kode skala internet untuk mengautomasi lokalisasi, integrasi, dan verifikasi artefak kode sumber yang dapat digunakan kembali melalui mekanisme weaving berbasis test cases.*

**Judul**
CodeGenie: A tool for test-driven source code search, 22nd International Conference on Object-Oriented Programming Systems, Languages, and Applications (OOPSLA 2007), ACM, 2007

**Penulis**
Otávio A.L. Lemos (Universidade de São Paulo), Sushil Krishna Bajracharya (UC Irvine), Joel Ossher (UC Irvine)

**Inti Paper**
Paper ini memperkenalkan **CodeGenie**, sebuah alat inovatif yang menggabungkan kebiasaan membuat tes sebelum menulis kode (*Test-Driven Development*) dengan pencarian kode otomatis. Alih-alih pengembang menulis fungsi dari nol setelah membuat tes, CodeGenie menggunakan informasi dari tes tersebut (seperti nama fungsi dan parameter) untuk mencari kode yang sudah ada di internet. Uniknya, alat ini secara otomatis mencoba memasukkan (*weaving*) kode hasil pencarian ke dalam proyek pengembang dan langsung menjalankan tes untuk melihat apakah kode tersebut benar-benar berfungsi. Pengembang tinggal memilih hasil terbaik yang lulus tes, sehingga sangat menghemat waktu pengembangan.



**Bedah Abstrak Mendetail**
1. **"We present CodeGenie, a tool that implements a test-driven approach to search and reuse of code available on largescale code repositories."**
   - *Maksud:* Peneliti memperkenalkan CodeGenie, alat yang menggunakan pendekatan berbasis pengujian untuk mencari dan menggunakan kembali kode dari gudang kode (repositori) skala besar.
2. **"With CodeGenie, developers design test cases for a desired feature first, similar to Test-driven Development (TDD)."**
   - *Maksud:* Pengembang membuat skenario pengujian terlebih dahulu untuk fitur yang diinginkan, persis seperti metode TDD yang umum di industri.
3. **"However, instead of implementing the feature from scratch, CodeGenie automatically searches for an existing implementation based on information available in the tests."**
   - *Maksud:* Bedanya, alih-alih mengetik sendiri kodenya, CodeGenie mencari otomatis kode yang sudah jadi di internet berdasarkan detail yang ada di dalam tes tersebut.
4. **"To check the suitability of the candidate results in the local context, each result is automatically woven into the developer's project and tested using the original tests."**
   - *Maksud:* Untuk memastikan kode yang ditemukan cocok, sistem secara otomatis memasangkan kode tersebut ke proyek pengembang dan menjalankan tes yang sudah dibuat tadi.
5. **"The developer can then reuse the most suitable result."**
   - *Maksud:* Pengembang tinggal mengambil hasil yang paling pas dan berhasil melewati semua pengujian.
6. **"Later, reused code can also be unwoven from the project as wished."**
   - *Maksud:* Jika tidak dibutuhkan lagi atau ingin diganti, kode tersebut bisa dilepaskan kembali dari proyek dengan mudah.
7. **"For the code searching and wrapping facilities, CodeGenie relies on Sourcerer, an Internet-scale source code infrastructure that we have developed."**
   - *Maksud:* Untuk urusan mencari dan membungkus kode, CodeGenie menggunakan infrastruktur bernama Sourcerer yang dikembangkan oleh tim peneliti yang sama.

**Baseline**
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai baseline infrastruktur pencarian kode berbasis struktur yang menyediakan data mentah untuk kemudian diolah oleh CodeGenie menjadi sistem pencarian berbasis tes.
* **Google Code Search (2006):** Digunakan sebagai pembanding sistem pencarian kode leksikal tradisional yang hanya mengandalkan teks tanpa kemampuan verifikasi fungsional kode.
* **Test-Driven Development (Beck, 2003):** Digunakan sebagai baseline metodologi pengembangan yang diadaptasi dari penulisan kode manual menjadi penemuan kode otomatis.
* **Koders & Krugle (2006):** Digunakan sebagai acuan teknologi mesin pencari kode komersial pada era tersebut untuk membedakan fitur *search-and-execute* milik CodeGenie.

**Keyword**
Source code reuse, Source code search, Test-driven development (TDD), Test-first, CodeGenie, Sourcerer.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah salah satu karya paling ikonik dalam riset "Code Search". Ia melampaui konsep "pencarian berdasarkan kata kunci" dan masuk ke ranah **"Pencarian Berdasarkan Perilaku" (Behavioral/Functional Search)**. Jika riset Anda ingin membahas bagaimana mesin pencari kode bisa menjamin kualitas hasil pencariannya, CodeGenie adalah referensi utama karena ia membuktikan bahwa tes otomatis adalah cara terbaik untuk memvalidasi hasil pencarian kode.

**Perbedaan dengan Paper Sebelumnya**
1. **Mekanisme Validasi:** Berbeda dengan paper **Sourcerer (2006)** yang hanya mencari berdasarkan struktur, CodeGenie melakukan **eksekusi nyata** untuk memvalidasi kode.
2. **Kueri:** Jika paper **MAPO (Xie & Pei, 2006)** menggunakan nama API sebagai kueri untuk mencari pola, CodeGenie menggunakan **unit test** sebagai kueri untuk mencari fungsionalitas.
3. **Automasi Integrasi:** Dibandingkan dengan **Component Reuse System (Washizaki & Fukazawa, 2005)** yang mengharuskan pengguna memeriksa komponen secara manual, CodeGenie mengautomasi proses integrasi (*weaving*) dan pengujian.
