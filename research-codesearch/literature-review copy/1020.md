# Sourcerer (Bajracharya et al., 2006)

*Sistem ini mengimplementasikan ekstraksi informasi struktural fine-grained dari repositori open-source ke dalam model relasional untuk memfasilitasi algoritma pemeringkatan CodeRank dan kueri berbasis struktur yang melampaui limitasi pencarian leksikal tradisional.*

**Judul**
Sourcerer: A search engine for open source code supporting structure-based search, 21st Annual ACM SIGPLAN Conference on Object-oriented Programming Systems, Languages, and Applications (OOPSLA 2006), ACM, 2006

**Penulis**
Sushil Krishna Bajracharya, Trung Chi Ngo, Erik J. Linstead, Yimeng Dou, Paul Rigor, Pierre F. Baldi, Cristina Videira Lopes (University of California, Irvine, Amerika Serikat)

**Inti Paper**
Paper ini memperkenalkan **Sourcerer**, sebuah mesin pencari canggih yang dirancang khusus untuk mencari kode sumber terbuka (*open-source*). Kebanyakan mesin pencari saat itu hanya bekerja seperti Google (mencari kata), tetapi Sourcerer mampu memahami struktur mendalam dari sebuah program, seperti bagaimana satu fungsi memanggil fungsi lainnya. Informasi struktural ini disimpan dalam database relasional. Dengan pemahaman struktur tersebut, Sourcerer memperkenalkan fitur **CodeRank** (mirip PageRank pada Google) untuk memeringkat kode mana yang paling penting atau paling sering digunakan, sehingga pengembang bisa menemukan contoh kode yang berkualitas tinggi dengan lebih mudah daripada hanya menggunakan pencarian kata kunci biasa.

**Bedah Abstrak Mendetail**
1. **"We present Sourcerer, a search engine for open-source code."**
   - *Maksud:* Peneliti memperkenalkan sistem baru bernama Sourcerer yang dikhususkan sebagai mesin pencari untuk proyek-proyek kode sumber terbuka.
2. **"Sourcerer extracts fine-grained structural information from the code and stores it in a relational model."**
   - *Maksud:* Sistem ini mengambil data teknis yang sangat mendetail tentang struktur internal kode (seperti hubungan antar kelas/objek) dan menyimpannya dalam model database teratur (relasional).
3. **"This information is used to implement a basic notion of CodeRank..."**
   - *Maksud:* Data struktur yang disimpan tersebut digunakan untuk menjalankan algoritma CodeRank, yaitu sistem penilaian otomatis untuk menentukan tingkat kepentingan atau popularitas suatu bagian kode.
4. **"...and to enable search forms that go beyond conventional keyword-based searches."**
   - *Maksud:* Dengan pemahaman struktur ini, Sourcerer memungkinkan pengguna melakukan pencarian yang jauh lebih cerdas dibandingkan sekadar mengetik kata kunci biasa, misalnya mencari kode berdasarkan pola hubungannya dengan bagian lain.

**Baseline**
* **Component Rank (Inoue et al., 2005):** Digunakan sebagai baseline untuk teknik pemeringkatan signifikansi komponen perangkat lunak berdasarkan hubungan penggunaan (use relations) antar komponen.
* **Google PageRank (Brin & Page, 1998):** Digunakan sebagai baseline konseptual untuk algoritma pemeringkatan web yang diadaptasi oleh Sourcerer menjadi CodeRank untuk domain kode sumber.
* **Micro Patterns (Gil & Maman, 2005):** Digunakan sebagai baseline untuk pemahaman pola-pola kecil dalam kode Java yang membantu dalam ekstraksi informasi struktural yang mendetail.
* **Jungloid Mining (Mandelin et al., 2005):** Digunakan sebagai baseline tandingan untuk sistem yang membantu pengembang menavigasi penggunaan API yang kompleks melalui teknik mining.

**Keyword**
CodeRank, Source code search, Relational model, Structure-based search, Open source code, Information retrieval.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah salah satu literatur fundamental dalam riset **Code Search**. Sourcerer menjawab tantangan utama dalam pencarian kode: bagaimana mencari melampaui teks mentah. Konsep menyimpan struktur kode ke dalam database relasional agar bisa dihitung "peringkat kepentingannya" (CodeRank) adalah kontribusi besar yang masih relevan hingga saat ini dalam pengembangan mesin pencari kode semantik dan struktural.

**Perbedaan dengan Paper Sebelumnya**
1. **Model Pemeringkatan:** Berbeda dengan paper **MAPO (Xie & Pei, 2006)** yang fokus pada penambangan pola urutan API, Sourcerer fokus pada **skalabilitas pemeringkatan** seluruh repositori menggunakan CodeRank.
2. **Representasi Data:** Jika paper **CodeQuest (Hajiyev et al., 2006)** menggunakan Datalog untuk kueri logika, Sourcerer lebih menekankan pada penggabungan pencarian berbasis teks dengan metadata struktural yang disimpan secara relasional.
3. **Unit Pencarian:** Dibandingkan dengan **Component Search (Washizaki & Fukazawa, 2004)** yang mencari komponen JavaBeans mandiri, Sourcerer menyediakan platform yang lebih luas untuk mencari berbagai fragmen kode sumber terbuka secara umum namun dengan dukungan struktur yang kuat.
