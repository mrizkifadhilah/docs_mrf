# Alattin (Thummalapenta & Xie, 2009)

*Penelitian ini mengusulkan algoritma penambangan pola alternatif berbasis logika disjungtif pada repositori kode sumber untuk mendeteksi 'neglected conditions' guna mereduksi tingkat false positive dalam verifikasi kepatuhan protokol API.*

**Judul**
Alattin: Mining alternative patterns for detecting neglected conditions, 24th IEEE/ACM International Conference on Automated Software Engineering (ASE 2009), IEEE, 2009

**Penulis**
Suresh Thummalapenta, Tao Xie (NC State College of Engineering, Raleigh, Amerika Serikat)

**Inti Paper**
Paper ini membahas masalah deteksi kesalahan pada perangkat lunak, khususnya kondisi yang sering terlupakan oleh pemrogram (*neglected conditions*) saat menggunakan API. Biasanya, alat pendeteksi kesalahan bekerja dengan cara mempelajari pola yang paling sering muncul di kode sumber. Masalahnya, jika ada dua cara yang berbeda namun sama-sama benar untuk menggunakan sebuah fungsi (API), alat tersebut sering kali menganggap cara yang jarang muncul sebagai kesalahan (ini disebut *false positive*). Peneliti mengembangkan **Alattin**, sebuah algoritma yang mampu mengenali **Pola Alternatif** (misalnya: "Gunakan cara A ATAU cara B"). Dengan mengenali bahwa ada lebih dari satu cara benar, Alattin berhasil mengurangi laporan kesalahan palsu hingga 28% dan membantu pengembang memastikan kode mereka lebih aman tanpa gangguan peringatan yang salah.



**Bedah Abstrak Mendetail**
1. **"To improve software quality, static or dynamic verification tools accept programming rules as input and detect their violations in software as defects."**
   - *Maksud:* Untuk meningkatkan kualitas perangkat lunak, alat verifikasi otomatis menerima aturan pemrograman dan mencari bagian kode yang melanggar aturan tersebut sebagai kerusakan.
2. **"As these programming rules are often not well documented in practice, previous work developed various approaches that mine programming rules as frequent patterns from program source code."**
   - *Maksud:* Karena aturan ini jarang dicatat di dokumen resmi, peneliti terdahulu membuat cara untuk menambang (mencari) aturan tersebut langsung dari pola yang paling sering muncul di kode program.
3. **"Then these approaches use static defect-detection techniques to detect pattern violations in source code under analysis."**
   - *Maksud:* Setelah pola ditemukan, teknik deteksi kerusakan digunakan untuk mencari kode mana saja yang tidak mengikuti pola umum tersebut.
4. **"These existing approaches often produce many false positives due to various factors."**
   - *Maksud:* Namun, cara lama ini sering memberikan peringatan salah (*false positive*) karena menganggap sesuatu yang beda sebagai kesalahan, padahal mungkin hanya cara alternatif yang benar.
5. **"To reduce false positives produced by these mining approaches, we develop a novel approach, called Alattin, that includes a new mining algorithm and a technique for detecting neglected conditions based on our mining algorithm."**
   - *Maksud:* Untuk mengurangi peringatan salah tersebut, peneliti membuat Alattin, sebuah sistem dengan algoritma baru untuk menemukan kondisi-kondisi yang terlupakan.
6. **"Our new mining algorithm mines alternative patterns in example form 'P1 or P2', where P1 and P2 are alternative rules such as condition checks on method arguments or return values related to the same API method."**
   - *Maksud:* Algoritma ini mencari pola alternatif dengan logika "P1 atau P2", misalnya pengecekan nilai balik yang bisa dilakukan dengan dua cara berbeda untuk satu fungsi yang sama.
7. **"Our evaluation results show that (1) alternative patterns reach more than 40% of all mined patterns for APIs provided by six open source libraries; (2) the mining of alternative patterns helps reduce nearly 28% of false positives among detected violations."**
   - *Maksud:* Hasil pengujian menunjukkan bahwa pola alternatif mencakup 40% dari seluruh pola yang ada, dan cara ini berhasil mengurangi hampir 28% peringatan salah.

**Baseline**
* **PR-miner (Li et al., 2005):** Digunakan sebagai baseline untuk teknik ekstraksi aturan pemrograman secara otomatis dari kode sumber berskala besar guna mendeteksi pelanggaran protokol.
* **Engler’s Deviant Behavior (Engler et al., 2001):** Digunakan sebagai baseline filosofis yang menganggap bug sebagai penyimpangan (*deviation*) dari pola perilaku mayoritas di dalam sistem.
* **Perracotta (Yang et al., 2006):** Digunakan sebagai baseline untuk penambangan aturan API temporal dari jejak eksekusi (*traces*) yang tidak sempurna.
* **Chang’s Neglected Conditions (Chang et al., 2007):** Digunakan sebagai baseline utama untuk membandingkan efektivitas deteksi kondisi yang terabaikan melalui analisis jalur kode.

**Keyword**
Alternative patterns, Neglected conditions, API mining, False positive reduction, Code search, Defect detection.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Mining for Search).**
Paper ini sangat relevan jika riset "Code Search" Anda bertujuan untuk **membangun mesin pencari yang "cerdas"**. Alattin memberikan teknik untuk memahami bahwa satu fungsionalitas bisa dicari/ditemukan dalam berbagai bentuk alternatif. Ini mendukung fitur pencarian yang lebih canggih, di mana sistem tidak hanya mencari kueri yang sama persis, tetapi memahami pola-pola alternatif yang valid di dalam kode sumber. Ini sangat berguna untuk bagian *indexing* dan *ranking* dalam mesin pencari kode Anda.

**Perbedaan dengan Paper Sebelumnya**
1. **Logika Pola:** Berbeda dengan paper **MAPO (2009)** yang fokus pada pola sekuensial (urutan 1-2-3), Alattin fokus pada pola **disjungtif** (A atau B).
2. **Tujuan Utama:** Jika paper **Sourcerer (2009)** mencari kode untuk digunakan kembali (*reuse*), Alattin melakukan pencarian pola untuk **verifikasi keamanan** dan kualitas kode (*bug detection*).
3. **Reduksi False Positive:** Dibandingkan dengan **SNIFF (2009)** yang meningkatkan relevansi melalui dokumentasi, Alattin meningkatkan relevansi hasil dengan memahami **fleksibilitas implementasi** di dalam kode sumber.
