# PARSEWeb (Thummalapenta & Xie, 2007)

*Sistem ini mengintegrasikan kueri berbasis transformasi tipe objek dengan teknik static analysis pada cuplikan kode yang dipanen secara on-demand melalui Code Search Engine (CSE) untuk mengekstraksi urutan pemanggilan metode yang optimal.*

**Judul**
PARSEWeb: A programmer assistant for reusing open source code on the web, 22nd IEEE/ACM International Conference on Automated Software Engineering (ASE'07), ACM, 2007

**Penulis**
Suresh Thummalapenta, Tao Xie (North Carolina State University, Amerika Serikat)

**Inti Paper**
Paper ini memperkenalkan **PARSEWeb**, sebuah alat bantu pintar untuk pemrogram yang bingung saat ingin mengubah satu jenis data (objek) menjadi jenis data lain menggunakan perpustakaan kode (*library*) tertentu. Masalah umum yang dihadapi pemrogram adalah: mereka tahu titik awal (objek A) dan titik tujuan (objek B), tapi tidak tahu urutan fungsi (*method sequence*) apa yang harus dipanggil untuk mencapainya. PARSEWeb bekerja dengan cara mencari contoh kode di internet lewat mesin pencari kode (CSE), lalu menganalisis kode-kode tersebut secara otomatis untuk menemukan "jalan pintas" atau urutan fungsi yang benar. Karena mencari secara langsung ke internet saat dibutuhkan (*on-demand*), alat ini tidak terbatas pada satu bahasa atau perpustakaan tertentu saja.



**Bedah Abstrak Mendetail**
1. **"Programmers commonly reuse existing frameworks or libraries to reduce software development efforts."**
   - *Maksud:* Pemrogram biasanya menggunakan kembali kerangka kerja atau perpustakaan kode yang sudah ada untuk menghemat waktu dan tenaga dalam membangun aplikasi.
2. **"One common problem in reusing the existing frameworks or libraries is that the programmers know what type of object that they need, but do not know how to get that object with a specific method sequence."**
   - *Maksud:* Masalah yang sering muncul adalah pemrogram tahu objek apa yang mereka inginkan, tapi buta mengenai urutan perintah atau fungsi yang harus diketik untuk menghasilkan objek tersebut.
3. **"To help programmers to address this issue, we have developed an approach that takes queries of the form 'Source object type → Destination object type' as input, and suggests relevant method-invocation sequences..."**
   - *Maksud:* Peneliti menciptakan solusi di mana pengguna cukup memasukkan kueri "Tipe A → Tipe B", dan sistem akan menyarankan urutan pemanggilan fungsi yang relevan sebagai solusinya.
4. **"Our approach interacts with a code search engine (CSE) to gather relevant code samples and performs static analysis over the gathered samples to extract required sequences."**
   - *Maksud:* Sistem ini berkomunikasi dengan mesin pencari kode untuk mengumpulkan contoh-contoh kode dari web, lalu membedah kode tersebut tanpa menjalankannya (*static analysis*) untuk mengambil urutan fungsi yang dicari.
5. **"As code samples are collected on demand through CSE, our approach is not limited to queries of any specific set of frameworks or libraries."**
   - *Maksud:* Karena data diambil langsung dari internet saat ada permintaan, alat ini sangat fleksibel dan bisa menjawab pertanyaan tentang perpustakaan kode apa pun yang tersedia di web.
6. **"We have implemented our approach with a tool called PARSEWeb, and conducted four different evaluations to show that our approach is effective in addressing programmer's queries."**
   - *Maksud:* Ide ini diwujudkan dalam alat bernama PARSEWeb dan telah diuji melalui empat jenis evaluasi untuk membuktikan bahwa alat ini benar-benar manjur.
7. **"We also show that PARSEWeb performs better than existing related tools: Prospector and Strathcona."**
   - *Maksud:* Peneliti membuktikan bahwa PARSEWeb bekerja lebih hebat dibandingkan alat pesaing yang sudah ada sebelumnya seperti Prospector dan Strathcona.

**Baseline**
* **Prospector (Mandelin et al., 2005):** Digunakan sebagai baseline utama untuk sistem yang menyarankan urutan pemanggilan fungsi, namun terbatas pada analisis lokal (bukan web-scale).
* **Strathcona (Holmes & Murphy, 2005):** Digunakan sebagai baseline untuk alat pemberi rekomendasi contoh kode yang berbasis pada konteks struktur kode di dalam editor (IDE).
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai acuan infrastruktur mesin pencari kode struktural yang memungkinkan pengambilan sampel kode secara efisien dari repositori terbuka.

**Keyword**
Code search engine, Method sequences, Code reuse, Static analysis, Object transformation, Programmer assistant.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah salah satu karya paling berpengaruh dalam bidang "Code Search". Jika riset Anda berfokus pada bagaimana hasil dari mesin pencari kode diolah menjadi solusi yang siap pakai (*actionable knowledge*), PARSEWeb adalah model dasarnya. Paper ini membuktikan bahwa mesin pencari kode bukan hanya soal "menemukan file", tapi bisa digunakan untuk **mensintesis solusi** berupa urutan pemanggilan API.

**Perbedaan dengan Paper Sebelumnya**
1. **Model Kueri:** Berbeda dengan **Sourcerer (2006)** atau **RiSE Search (2006)** yang menggunakan kata kunci atau kueri struktural, PARSEWeb menggunakan kueri **transformasi tipe data** (Source $\rightarrow$ Destination).
2. **Sumber Data:** Jika **Prospector (2005)** hanya menganalisis kode yang ada di komputer lokal, PARSEWeb mengambil data secara **on-demand dari seluruh web** melalui mesin pencari kode.
3. **Hasil Akhir:** Dibandingkan dengan **CodeGenie (2007)** yang mencari satu blok kode utuh untuk lulus tes, PARSEWeb berfokus pada ekstraksi **urutan pemanggilan metode spesifik** dari berbagai sumber kode yang berbeda.
