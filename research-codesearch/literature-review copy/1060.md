# Comment-Reuse (Álvarez-González et al., 2009)

*Penelitian ini merumuskan metodologi standardisasi anotasi berbasis struktur komentar formal untuk mengoptimasi indeksasi fungsional pada mesin pencari kode dan mereduksi beban kognitif dalam prosedur pemahaman artefak perangkat lunak.*

**Judul**
A method to write quality code comment to reuse source code, Proceedings of the 4th Indian International Conference on Artificial Intelligence (IICAI 2009), IICAI, 2009

**Penulis**
Rubén Álvarez-González, Sonia Sánchez-Cuadrado, Ángela Goñi Moreno, Juan B. Castellanos Peñuela (Universidad Politécnica de Madrid & Universidad Carlos III de Madrid, Spanyol)

**Inti Paper**
Paper ini menyoroti masalah utama pada alat pencari kode: meskipun alat tersebut bisa menemukan kode, mereka tidak membantu pengembang untuk benar-benar memahami kode yang ditemukan. Jika seorang ahli perangkat lunak tidak paham kode tersebut, mereka akan kesulitan untuk menggunakannya kembali (*reuse*). Peneliti mengusulkan sebuah metode untuk membuat komentar kode yang berkualitas secara mudah dan terstruktur. Tujuannya ada dua: pertama, agar manusia lebih cepat memahami logika kode tersebut; kedua, agar mesin pencari kode masa depan bisa mencari kode berdasarkan "fungsinya" (apa yang dilakukan kode tersebut) melalui struktur komentar tersebut, bukan sekadar mencocokkan teks kueri secara acak.



**Bedah Abstrak Mendetail**
1. **"Code retrieval tools do not support the correct understanding of retrieval code."**
   - *Maksud:* Alat pencari kode saat ini tidak membantu pengguna untuk memahami dengan benar kode yang telah berhasil ditemukan.
2. **"However, it is very important for a software expert to be able to understand the code recovered using such a tool."**
   - *Maksud:* Padahal, sangatlah penting bagi seorang ahli perangkat lunak untuk bisa mengerti kode yang didapat dari alat tersebut.
3. **"If the expert do not understand this code, it would be difficult for him to reuse it."**
   - *Maksud:* Jika si ahli tidak paham kode ini, dia akan merasa kesulitan untuk menggunakan kembali kode tersebut dalam proyeknya.
4. **"Due to that fact, this paper proposes a method to develop quality comments in an easy way in order to facilitate code reusability."**
   - *Maksud:* Berdasarkan kenyataan itu, makalah ini mengusulkan sebuah metode mudah untuk membuat komentar berkualitas demi mempermudah penggunaan kembali kode.
5. **"The understanding of code is improved by these comments."**
   - *Maksud:* Kemampuan manusia dalam memahami kode akan meningkat berkat adanya komentar-komentar berkualitas ini.
6. **"In addition, by using the comment-structure proposed in this work it is possible to develop code retrieval tools which are able to find source code by functionality."**
   - *Maksud:* Selain itu, dengan menggunakan struktur komentar yang diusulkan di sini, kita bisa membuat alat pencari kode yang mampu menemukan kode berdasarkan fungsi atau kegunaannya secara spesifik.

**Baseline**
* **Frakes’ Reuse Research (Frakes & Kang, 2005):** Digunakan sebagai baseline studi mengenai status dan tantangan dalam riset penggunaan kembali perangkat lunak (*software reuse*) secara global.
* **Ambysoft Java Coding Standards (Ambysoft, 2000):** Digunakan sebagai baseline standar penulisan kode dan dokumentasi Java konvensional untuk dibandingkan dengan metode komentar terstruktur yang diusulkan.
* **RIAO 04 Information Retrieval (RIAO, 2004):** Digunakan sebagai baseline teknologi pencarian informasi berbasis teks untuk menunjukkan kelemahan pencarian tanpa pemahaman konteks fungsional.
* **Lexesp Spanish Corpus (Lexesp, 2000):** Digunakan sebagai acuan linguistik dalam pemrosesan bahasa alami untuk mendukung standarisasi kata kunci dalam komentar.

**Keyword**
Code retrievals, Code reusability, Source codes, Quality comments, Functional search.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Metadata & Indexing).**
Paper ini sangat relevan jika riset Anda membahas tentang **"Kualitas Indeksasi"**. Dalam riset *Code Search*, mesin pencari hanya sehebat data yang diindeksnya. Paper ini memberikan solusi dari sisi hulu (penulisan kode) agar kode lebih mudah ditemukan dan dipahami. Ini bisa menjadi argumen kuat dalam riset Anda bahwa pencarian kode yang efektif membutuhkan sinergi antara algoritma pencarian dan kualitas dokumentasi internal (komentar) yang terstruktur.

**Perbedaan dengan Paper Sebelumnya**
1. **Sisi Intervensi:** Berbeda dengan paper **Sourcerer (2009)** yang fokus pada algoritma pencarian pada kode yang sudah ada, paper ini fokus pada **cara menulis komentar** agar kode tersebut *searchable* di masa depan.
2. **Tujuan Akhir:** Jika paper **SNIFF (2009)** menggunakan dokumentasi luar (API docs) untuk memahami kode, paper ini menggunakan **komentar di dalam kode itu sendiri** yang dibuat dengan aturan khusus.
3. **Pencarian Berbasis Fungsi:** Dibandingkan dengan **Samurai (2009)** yang membedah nama variabel, paper ini mencoba melakukan pencarian berdasarkan **deskripsi fungsional** yang tertuang dalam komentar terstandar.
