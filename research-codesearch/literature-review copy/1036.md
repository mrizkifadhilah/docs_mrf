# Code Conjurer (Hummel et al., 2008)

*Sistem ini mengintegrasikan mekanisme penambangan artefak kode sumber secara proaktif melalui ekstraksi tanda tangan antarmuka dan metadata pengujian untuk mengeksekusi test-driven search yang terintegrasi pada lingkungan pengembangan terpadu.*

**Judul**
Code conjurer: Pulling reusable software out of thin air, IEEE Software, IEEE Computer Society, 2008

**Penulis**
Oliver Hummel, Werner Janjic, Colin Atkinson (Universität Mannheim, Jerman)

**Inti Paper**
Paper ini memperkenalkan **Code Conjurer**, sebuah alat berbentuk *plug-in* untuk Eclipse yang dirancang untuk mempermudah pemrogram dalam menemukan dan menggunakan kembali kode yang sudah ada di internet. Biasanya, penggunaan kembali kode (*reuse*) secara sistematis dianggap sangat berat dan rumit. Code Conjurer bekerja secara cerdas: saat seorang pemrogram sedang mengetik kode, alat ini secara otomatis mengambil informasi tentang antarmuka (*interface*) dan rencana pengujian (*test cases*) yang sedang dibuat. Informasi ini kemudian digunakan untuk mencari kode di mesin pencari kode secara otomatis tanpa mengganggu pekerjaan pemrogram. Jika ditemukan kode yang cocok dan lolos pengujian, alat ini akan membantu memasukkan kode tersebut ke dalam proyek dengan sangat mudah, seolah-olah "memunculkan kode dari udara kosong."



**Bedah Abstrak Mendetail**
1. **"Accelerating the software development process by assembling new applications from existing software assets has been a goal of the IT industry for many years."**
   - *Maksud:* Mempercepat pembuatan perangkat lunak dengan cara menyusun aplikasi dari komponen kode yang sudah ada telah menjadi impian industri IT sejak lama.
2. **"However, most of today's systematic software reuse uses heavyweight approaches such as product-line engineering."**
   - *Maksud:* Sayangnya, cara-cara yang ada saat ini untuk menggunakan kembali kode biasanya sangat rumit dan berat untuk diterapkan (seperti teknik *product-line engineering*).
3. **"Now, with the explosion in open source software repositories and the advent of a new generation of powerful software search engines, this is set to change."**
   - *Maksud:* Namun sekarang, dengan meledaknya jumlah kode gratis (open source) dan munculnya mesin pencari kode yang canggih, situasi ini akan berubah menjadi lebih mudah.
4. **"Code Conjurer is an Eclipse plug-in that extracts interface and test information from a developer's coding activities and uses this information to issue test-driven searches to a code-search engine."**
   - *Maksud:* Code Conjurer adalah alat tambahan untuk Eclipse yang secara otomatis mengambil info tentang struktur kode dan tes yang sedang dikerjakan pemrogram, lalu melakukan pencarian otomatis ke internet berdasarkan info tersebut.
5. **"It presents components matching the developer's needs as reuse recommendations without disturbing the development work."**
   - *Maksud:* Alat ini akan memberikan saran potongan kode yang cocok dengan kebutuhan pemrogram secara diam-diam tanpa mengalihkan perhatian pemrogram dari pekerjaannya.
6. **"Automated dependency resolution then allows selected components to be woven into the current project with minimal manual effort."**
   - *Maksud:* Setelah kode dipilih, sistem akan menangani urusan teknis (seperti ketergantungan antar file) agar kode tersebut bisa langsung terpasang di proyek dengan sedikit usaha manual saja.

**Baseline**
* **CodeGenie (Lemos et al., 2007):** Digunakan sebagai baseline untuk alat pencarian kode berbasis pengujian (*test-driven search*) yang memvalidasi hasil pencarian melalui eksekusi unit test.
* **Extreme Harvesting (Hummel, 2004):** Digunakan sebagai baseline metodologi penemuan komponen secara agresif (agile reuse) yang dikembangkan oleh penulis sebelumnya.
* **Mili (Mili et al., 1998):** Digunakan sebagai baseline untuk studi literatur mengenai perpustakaan penggunaan kembali perangkat lunak (*software reuse libraries*).

**Keyword**
Code search engine, Test-driven search, Software reuse, Eclipse plug-in, Component-based development, Reuse recommendation.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini adalah salah satu tonggak penting dalam riset **"Proactive Code Search"**. Jika riset Anda membahas tentang bagaimana sistem pencarian bisa membantu pengembang secara otomatis tanpa harus mengetik kueri secara manual (pencarian di balik layar), Code Conjurer adalah referensi utama. Paper ini memberikan contoh nyata integrasi antara mesin pencari kode (CSE) dengan alur kerja nyata di IDE.

**Perbedaan dengan Paper Sebelumnya**
1. **Otomatisasi Kueri:** Berbeda dengan paper **Sourcerer (2006)** yang mengharuskan pengguna mengetik kueri, Code Conjurer **mengekstrak kueri secara otomatis** dari aktivitas penulisan kode.
2. **Integrasi Weaving:** Jika paper **PARSEWeb (2007)** hanya memberikan urutan API, Code Conjurer melakukan **dependency resolution** untuk memastikan komponen yang diambil benar-benar bisa langsung dijalankan di proyek.
3. **Fokus Pengguna:** Dibandingkan dengan **CodeGenie (2007)** yang lebih berfokus pada validasi tes, Code Conjurer lebih menekankan pada **aspek produktivitas** agar proses pencarian tidak mengganggu (*unobtrusive*) alur kerja pengembang.
