# CodeGenie (Lemos et al., 2009)

*Sistem ini mengimplementasikan paradigma Test-Driven Code Search (TDCS) yang memanfaatkan unit test sebagai spesifikasi formal untuk mengeksekusi penelusuran artefak kode pada repositori Sourcerer guna menjamin kompatibilitas perilaku dan integrasi fungsional otomatis.*

**Judul**
Applying test-driven code search to the reuse of auxiliary functionality, Proceedings of the 24th Annual ACM Symposium on Applied Computing (SAC 2009), ACM, 2009

**Penulis**
Otávio A.L. Lemos (Universidade de São Paulo), Sushil Krishna Bajracharya, Joel Ossher, Paulo Cesar Masiero, Cristina Videira Lopes (University of California, Irvine)

**Inti Paper**
Paper ini memperkenalkan pendekatan **Test-Driven Code Search (TDCS)** untuk membantu pemrogram menemukan fungsi bantuan (*auxiliary functionality*)—seperti kompresi file atau enkripsi data—di internet. Masalahnya, mencari kode secara manual di mesin pencari seperti Google sering kali melelahkan dan rawan kesalahan karena pemrogram harus memeriksa kode satu per satu. Peneliti mengembangkan **CodeGenie**, sebuah *plugin* Eclipse yang memungkinkan pemrogram menulis "unit test" (skenario pengujian) terlebih dahulu. CodeGenie kemudian menggunakan pengujian tersebut untuk mencari kode di mesin pencari **Sourcerer** dan secara otomatis menguji apakah hasil yang ditemukan benar-benar bekerja sesuai keinginan di komputer pemrogram.



**Bedah Abstrak Mendetail**
1. **"Software developers spend considerable effort implementing auxiliary functionality used by the main features of a system (e.g. compressing/ decompressing files, encryption/decription of data, scaling/rotating images)."**
   - *Maksud:* Pengembang menghabiskan banyak waktu hanya untuk membuat fungsi-fungsi pendukung (seperti mengecilkan ukuran gambar atau mengamankan data) yang sebenarnya bukan fitur utama aplikasi.
2. **"With the increasing amount of open source code available on the Internet, time and effort can be saved by reusing these utilities through informal practices of code search and reuse."**
   - *Maksud:* Karena sekarang banyak kode gratis di internet, pengembang bisa menghemat waktu jika mereka mencari dan memakai ulang kode-kode tersebut.
3. **"However, when this type of reuse is performed in an ad hoc manner, it can be tedious and error-prone: code results have to be manually inspected and extracted into the workspace."**
   - *Maksud:* Tapi, jika mencari asal-asalan, prosesnya jadi membosankan dan berisiko salah, karena kode harus diperiksa dan dipindahkan ke proyek secara manual.
4. **"In this paper we introduce the use of test cases as an interface for automating code search and reuse and evaluate its applicability and performance in the reuse of auxiliary functionality."**
   - *Maksud:* Peneliti mengusulkan penggunaan "skenario pengujian" sebagai cara otomatis untuk mencari dan memakai kode, lalu menguji apakah cara ini efektif untuk fungsi-fungsi pendukung tadi.
5. **"We call our approach Test-Driven Code Search (TDCS)."**
   - *Maksud:* Mereka menamakan metode ini Test-Driven Code Search (Pencarian Kode Berbasis Pengujian).
6. **"Test cases serve two purposes: (1) they define the behavior of the desired functionality to be searched; and (2) they test the matching results for suitability in the local context."**
   - *Maksud:* Skenario pengujian punya dua fungsi: sebagai penentu ciri-ciri kode yang dicari, dan sebagai alat tes untuk memastikan kode yang ditemukan cocok dengan proyek pengembang.
7. **"We present CodeGenie, an Eclipse plugin that performs TDCS using a code search engine called Sourcerer."**
   - *Maksud:* Peneliti menciptakan CodeGenie, sebuah alat tambahan untuk Eclipse yang menjalankan metode TDCS dengan bantuan mesin pencari kode bernama Sourcerer.
8. **"Our evaluation presents evidence of the applicability and good performance of TDCS in the reuse of auxiliary functionality."**
   - *Maksud:* Hasil evaluasi membuktikan bahwa metode TDCS ini sangat berguna dan kinerjanya bagus untuk membantu pengembang memakai kembali fungsi-fungsi pendukung.

**Baseline**
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai baseline infrastruktur mesin pencari kode berbasis struktur yang menyediakan data bagi CodeGenie untuk melakukan pencarian.
* **Jigsaw (Cottrell et al., 2008):** Digunakan sebagai baseline untuk alat penggunaan kembali kode (*reuse tool*) skala kecil yang membantu integrasi potongan kode ke dalam proyek.
* **Assieme (Hoffmann et al., 2007):** Digunakan sebagai baseline antarmuka pencarian web untuk pemrogram yang berfokus pada referensi konten sebagai perbandingan efisiensi pencarian manual.
* **Pragmatic Reuse Tools (Holmes & Murphy, 2007):** Digunakan sebagai baseline pendekatan penggunaan kembali kode secara praktis yang melibatkan perencanaan dan investigasi manual oleh pengembang.

**Keyword**
Test-Driven Code Search (TDCS), CodeGenie, Sourcerer, Software Reuse, Unit Testing.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini sangat krusial jika riset Anda berfokus pada **validasi hasil pencarian kode**. CodeGenie menjawab salah satu tantangan terbesar dalam *Code Search*: "Bagaimana kita tahu kode yang ditemukan dari internet benar-benar berfungsi?". Dengan menggunakan *test case* sebagai kueri sekaligus filter, paper ini memberikan fondasi yang kuat untuk otomatisasi pencarian kode yang terpercaya.

**Perbedaan dengan Paper Sebelumnya**
1. **Mekanisme Kueri:** Berbeda dengan paper **Sourcerer (2009)** yang mencari berdasarkan kata kunci atau topik, CodeGenie menggunakan **Unit Test** sebagai kueri.
2. **Otomatisasi Validasi:** Jika paper **SNIFF (2009)** hanya memberikan cuplikan kode yang relevan secara semantik, CodeGenie melakukan **eksekusi kode** secara otomatis untuk memastikan fungsi tersebut berjalan (dinamis).
3. **Fokus Kegunaan:** Dibandingkan dengan **MAPO (2009)** yang memberikan pola penggunaan API, CodeGenie fokus pada penyediaan **potongan kode utuh (standalone)** yang siap pakai untuk tugas-tugas spesifik.
