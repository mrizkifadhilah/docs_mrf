# D-CUBED (Wȩgrzynowicz & Stencel, 2009)

*Sistem ini mengimplementasikan mesin kueri kode semantik berbasis symbolic instances untuk mengekstraksi relasi call-flow dan data-flow melalui analisis statis guna mendeteksi pola desain, defek keamanan, dan anti-patterns pada aplikasi Java.*

**Judul**
The good, the bad, and the ugly - Three ways to use a semantic code query system, OOPSLA 2009 Companion - 24th Annual ACM Conference on Object-Oriented Programming, Systems, Languages and Applications, ACM, 2009

**Penulis**
Patrycja Wȩgrzynowicz (Research and Academic Computer Network (NASK), Polandia), Krzysztof Stencel (University of Warsaw, Polandia)

**Inti Paper**
Paper ini memperkenalkan **D-CUBED**, sebuah sistem pencarian kode canggih untuk bahasa pemrograman Java. Berbeda dengan mesin pencari kode biasa yang hanya mencari teks, D-CUBED adalah sistem pencari **semantik** yang memahami "perilaku" sebuah program. Sistem ini menggunakan teknik analisis statis untuk melacak aliran data (*data flow*) dan aliran pemanggilan fungsi (*call flow*). Peneliti membagi kegunaan sistem ini menjadi tiga skenario unik: (1) "The Good": Menemukan pola desain yang baik secara otomatis; (2) "The Bad": Menemukan kesalahan (*bugs*) dan celah keamanan yang berbahaya; serta (3) "The Ugly": Menilai kualitas desain dengan menemukan praktik pengodean yang buruk atau berantakan.



**Bedah Abstrak Mendetail**
1. **"D-CUBED is a semantic code query system for Java."**
   - *Maksud:* D-CUBED adalah sebuah sistem mesin pencari kode berbasis semantik (makna/logika) yang dikhususkan untuk bahasa Java.
2. **"Its focus is on capturing the semantics of an analyzed program."**
   - *Maksud:* Fokus utama sistem ini adalah menangkap maksud dan logika perilaku dari sebuah program yang sedang dianalisis.
3. **"It provides rich support to investigate the call flow and data flow of a program by using static analysis techniques with the custom model of symbolic instances."**
   - *Maksud:* Sistem ini memberikan kemampuan mendalam untuk menyelidiki alur pemanggilan fungsi dan alur data menggunakan teknik analisis tanpa menjalankan program (*static analysis*) dengan model representasi khusus.
4. **"The usage scenarios of D-CUBED include: (1) detection of design patterns with the focus on code semantics (the good)..."**
   - *Maksud:* Skenario pertama adalah mendeteksi pola desain yang rapi dan benar (Good) berdasarkan logika kodenya.
5. **"(2) discovery of bugs, including a range of security holes (the bad)..."**
   - *Maksud:* Skenario kedua adalah menemukan kesalahan program dan celah keamanan yang berisiko (Bad).
6. **"(3) assessment and improvement of a design by discovering bad design and code practices (the ugly)."**
   - *Maksud:* Skenario ketiga adalah mengevaluasi dan memperbaiki desain program dengan menemukan praktik-praktik pengodean yang buruk atau tidak efisien (Ugly).

**Baseline**
* **CodeQuest (Hajiyev et al., 2005):** Digunakan sebagai baseline sistem kueri kode sumber yang menggunakan bahasa Datalog untuk melakukan kueri terhadap database kode.
* **JQuery (McCormick & de Alwis, 2004):** Digunakan sebagai baseline alat navigasi dan pencarian kode yang membantu pengembang menelusuri hubungan kode yang kompleks di dalam IDE.

**Keyword**
Semantic code query, Static analysis, Design patterns, Bug discovery, Data flow analysis.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Advanced Query).**
Paper ini sangat relevan jika riset Anda mengarah pada **Structural/Semantic Code Search**. D-CUBED bukan sekadar mencari potongan kode untuk disalin, melainkan sebuah sistem pencari untuk menginvestigasi basis kode yang besar. Jika riset Anda membahas bagaimana sistem pencari dapat membantu pengembang memahami hubungan antar komponen (seperti aliran data), maka paper ini adalah contoh implementasi yang sangat kuat tentang bagaimana kueri kode dapat digunakan untuk analisis kualitas.

**Perbedaan dengan Paper Sebelumnya**
1. **Model Analisis:** Berbeda dengan paper **Sourcerer (2009)** yang lebih fokus pada indeksasi struktural tingkat tinggi, D-CUBED melakukan analisis mendalam hingga ke level **aliran data (data flow)**.
2. **Klasifikasi Hasil:** Jika paper **SNIFF (2009)** hanya menyajikan hasil yang relevan, D-CUBED mengategorikan hasil pencariannya berdasarkan **kualitas kode** (Good, Bad, Ugly).
3. **Tujuan Kueri:** Dibandingkan dengan **CodeGenie (2009)** yang mencari kode untuk dipakai kembali (*reuse*), D-CUBED lebih difokuskan pada **inspeksi kode** dan pemeliharaan perangkat lunak.
