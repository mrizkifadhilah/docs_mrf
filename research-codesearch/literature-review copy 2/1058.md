# S6 (Reiss, 2009)

*Penelitian ini mengusulkan sistem S6 yang mengintegrasikan teknik temu kembali artefak kode dengan transformasi program otomatis (program transformations) berbasis semantik untuk merekonsiliasi diskrepansi antara representasi komponen repositori dan spesifikasi formal pengguna.*

**Judul**
Semantics-based code search, 31st International Conference on Software Engineering (ICSE 2009), IEEE, 2009

**Penulis**
Steven P. Reiss (Brown University, Providence, Amerika Serikat)

**Inti Paper**
Paper ini memperkenalkan sistem bernama **S6**. Tujuannya adalah membantu pemrogram membuat fungsi atau kelas baru dengan cara mencarinya di gudang kode terbuka (open source). Berbeda dengan mesin pencari biasa, S6 memungkinkan pengguna memberikan instruksi yang sangat detail (spesifikasi), seperti kata kunci, tipe data (signature), pengujian otomatis (*test cases*), aturan keamanan, dan kontrak logika. Hebatnya, S6 tidak hanya "mencari", tetapi juga "mengubah" kode yang ditemukan agar benar-benar pas dengan permintaan pengguna. Jika kode yang ditemukan hampir benar tapi nama variabelnya salah atau urutan parameternya berbeda, sistem akan melakukan transformasi otomatis untuk memperbaikinya sebelum diberikan kepada pemrogram.



**Bedah Abstrak Mendetail**
1. **"Our goal is to use the vast repositories of available open source code to generate specific functions or classes that meet a user's specifications."**
   - *Maksud:* Tujuan peneliti adalah menggunakan gudang kode sumber terbuka yang sangat luas untuk menciptakan fungsi atau kelas tertentu yang sesuai dengan instruksi detail dari pengguna.
2. **"The key words here are specifications and generate."**
   - *Maksud:* Kata kunci utama dalam penelitian ini adalah "spesifikasi" (instruksi detail) dan "generasi" (proses menghasilkan kode yang pas).
3. **"We let users specify what they are looking for as precisely as possible using keywords, class or method signatures, test cases, contracts, and security constraints."**
   - *Maksud:* Peneliti membiarkan pengguna menjelaskan apa yang mereka cari sedetail mungkin menggunakan kata kunci, bentuk fungsi/kelas, skenario pengujian, kontrak logika, hingga batasan keamanan.
4. **"Our system then uses an open set of program transformations to map retrieved code into what the user asked for."**
   - *Maksud:* Sistem kemudian menggunakan sekumpulan aturan perubahan program untuk mengubah kode yang ditemukan di internet agar sesuai dengan permintaan unik pengguna.
5. **"This approach is implemented in a prototype system for Java with a web interface."**
   - *Maksud:* Pendekatan ini diterapkan dalam sebuah model purwarupa untuk bahasa pemrograman Java yang dapat diakses melalui antarmuka web.

**Baseline**
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai baseline infrastruktur pencarian kode berbasis struktur untuk membandingkan efektivitas pengambilan artefak sebelum dilakukan proses transformasi semantik.
* **JML Tools (Burdy et al., 2005):** Digunakan sebagai baseline untuk penggunaan kontrak logika dan spesifikasi formal dalam memverifikasi perilaku kode yang diambil.
* **Drummond (Drummond et al., 2000):** Digunakan sebagai baseline untuk agen pembelajaran yang membantu penjelajahan perpustakaan perangkat lunak secara cerdas.
* **Behavior-based Retrieval (Chou et al., 1996):** Digunakan sebagai baseline untuk teknik temu kembali komponen berdasarkan perilaku (behavior) dan spesifikasi berorientasi objek.

**Keyword**
Semantics-based search, Program transformations, Code generation, Test-driven search, Java code search.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Must-Read).**
Paper ini adalah salah satu karya paling revolusioner dalam bidang *Code Search*. Jika riset Anda membahas tentang bagaimana meningkatkan akurasi hasil pencarian hingga ke level fungsional, S6 adalah referensi wajib. S6 melampaui konsep "mencari" dan masuk ke area "transformasi", yang membuktikan bahwa seringkali kode yang kita cari sudah ada di internet, hanya saja bentuknya sedikit berbeda dari yang kita butuhkan. Paper ini memberikan solusi teknis untuk menjembatani celah tersebut.

**Perbedaan dengan Paper Sebelumnya**
1. **Transformasi Kode:** Berbeda dengan paper **Sourcerer (2009)** atau **SNIFF (2009)** yang hanya memberikan kode "apa adanya", S6 secara aktif **mengubah (transform)** kode tersebut agar sesuai dengan spesifikasi pengguna.
2. **Kekuatan Spesifikasi:** Jika paper **MAPO (2009)** mengandalkan pola penggunaan API, S6 mengandalkan **Test Cases dan Kontrak Logika** untuk menjamin bahwa kode yang ditemukan benar-benar berjalan sesuai keinginan.
3. **Hasil Akhir:** Dibandingkan dengan **CodeGenie (2009)** yang juga menggunakan tes, S6 lebih canggih karena memiliki lapisan **Program Transformations** yang bisa mengubah struktur kode (seperti mengganti tipe data atau urutan argumen) agar lulus pengujian tersebut.
