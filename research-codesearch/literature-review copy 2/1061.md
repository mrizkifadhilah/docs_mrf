# SCA-Edu (Stanford & Erbach, 2009)

*Penelitian ini menginvestigasi efikasi teknik static code analysis melalui evaluasi komparatif antara artefak kode profesional dan mahasiswa menggunakan tool FindBugs guna mengidentifikasi pola defek semantik dan sintaksis dalam konteks pedagogi ilmu komputer.*

**Judul**
Exploring software quality with static code analysis: Examining professional and student mistakes to improve undergraduate instruction, 20th Midwest Artificial Intelligence and Cognitive Science Conference (MAICS 2009), MAICS, 2009

**Penulis**
Jeff Stanford (Indiana University-Purdue University Fort Wayne), David Erbach (Western Kentucky University)

**Inti Paper**
Paper ini membahas penggunaan analisis kode statis (*Static Code Analysis*), yaitu cara memeriksa kesalahan dalam program komputer tanpa harus menjalankan program tersebut. Peneliti berargumen bahwa teknik ini sangat penting untuk mengurangi risiko adanya "bug" atau kerusakan pada aplikasi saat dirilis. Mereka meninjau berbagai alat otomatis (gratis maupun berbayar) dan menyimpulkan bahwa **FindBugs** adalah alat gratis terbaik untuk bahasa pemrograman Java. Melalui studi kasus yang membandingkan kode buatan pengembang profesional dengan kode buatan mahasiswa, peneliti memberikan saran kepada dosen ilmu komputer tentang bagaimana cara memperbaiki tugas kuliah agar mahasiswa tidak melakukan kesalahan yang sama berulang kali.



**Bedah Abstrak Mendetail**
1. **"Static code analysis is a technique used to analyze code without executing the program."**
   - *Maksud:* Analisis kode statis adalah sebuah teknik yang digunakan untuk memeriksa baris-baris kode tanpa perlu menjalankan aplikasinya.
2. **"It has been shown to be an effective technique to help mitigate the risks of delivering software containing bugs."**
   - *Maksud:* Teknik ini terbukti efektif dalam membantu mengurangi risiko mengirimkan perangkat lunak yang masih memiliki kesalahan (bug) kepada pengguna.
3. **"This paper defends the need for performing static code analysis and examines the myths, limitations, and challenges of using it."**
   - *Maksud:* Makalah ini membela alasan mengapa kita perlu melakukan analisis kode statis serta memeriksa mitos, batasan, dan tantangan dalam penggunaannya.
4. **"Previous research is studied to evaluate the automated tools available (both free and commercial)."**
   - *Maksud:* Penelitian-penelitian terdahulu dipelajari untuk menilai berbagai alat otomatis yang ada di pasaran, baik yang gratis maupun yang komersial.
5. **"FindBugs surfaces as the best free static code analysis tool."**
   - *Maksud:* Hasilnya menunjukkan bahwa FindBugs muncul sebagai alat analisis kode statis gratis yang paling unggul.
6. **"A case study is developed and examined using professional and student code."**
   - *Maksud:* Sebuah studi kasus disusun dan diuji menggunakan contoh kode asli dari pekerja profesional dan juga mahasiswa.
7. **"Recommendations and lessons learned are reviewed, including suggestions to undergraduate computer science instructors for improving assignments."**
   - *Maksud:* Rekomendasi dan pelajaran yang didapat diulas kembali, termasuk saran bagi para pengajar di jurusan ilmu komputer untuk memperbaiki cara mereka memberikan tugas kuliah.

**Baseline**
* **FindBugs (Hovemeyer & Pugh, 2003):** Digunakan sebagai baseline alat deteksi bug statis utama untuk mengidentifikasi pola kesalahan pada *bytecode* Java melalui teknik observasi pola deteksi.
* **Louridas (Louridas, 2006):** Digunakan sebagai baseline studi literatur mengenai prinsip dasar dan manfaat penerapan analisis kode statis dalam industri perangkat lunak.
* **Ayewah (Ayewah et al., 2007):** Digunakan sebagai baseline untuk mengevaluasi peringatan defek (*defect warnings*) yang dihasilkan oleh alat analisis statis pada perangkat lunak produksi massal.
* **Rutar (Rutar et al., 2004):** Digunakan sebagai baseline perbandingan antara berbagai alat pencari bug khusus untuk Java untuk menentukan keunggulan fungsional masing-masing alat.

**Keyword**

**Kelayakan untuk Riset "CODE SEARCH"**
**TIDAK LAYAK.**
Fokus utama paper ini adalah pada **analisis kualitas kode** dan **pendidikan**, bukan pada mekanisme pencarian kode (*Code Search*). "Pencarian" yang dilakukan di sini adalah pencarian otomatis terhadap pola *bug* di dalam satu file atau proyek untuk tujuan pengecekan kesalahan, bukan pencarian informasi atau kode fungsional di internet/repositori besar yang menjadi inti riset Anda. Jika riset Anda murni tentang *Information Retrieval* (IR) pada kode sumber, paper ini tidak memberikan kontribusi pada sisi algoritma atau metode pencariannya.

**Perbedaan dengan Paper Sebelumnya**
1. **Tujuan Utama:** Berbeda dengan paper **Sourcerer (2009)** yang membangun mesin pencari untuk penggunaan kembali (*reuse*), paper ini menggunakan alat analisis untuk **pendidikan dan evaluasi kesalahan**.
2. **Subjek:** Jika paper **SNIFF (2009)** membantu pengembang mencari API, paper ini membantu dosen **mengevaluasi kualitas tugas mahasiswa**.
3. **Metode:** Dibandingkan dengan **LDA Bug Localization (2008)** yang mencari lokasi bug menggunakan statistik bahasa, paper ini menggunakan **analisis statis berbasis aturan (*rule-based*)** yang sudah tertanam dalam alat FindBugs.
