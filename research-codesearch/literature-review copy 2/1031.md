# CodeGenie (Lemos et al., 2007)

*Sistem ini mengautomasi siklus hidup rekayasa perangkat lunak melalui integrasi pengujian unit sebagai deskriptor kueri untuk melakukan temu kembali kode sumber skala internet yang divalidasi via mekanisme dynamic execution dan code weaving.*

**Judul**
CodeGenie: Using test-cases to search and reuse source code, 22nd IEEE/ACM International Conference on Automated Software Engineering (ASE'07), ACM, 2007

**Penulis**
Otávio A.L. Lemos (Universidade de São Paulo), Sushil Krishna Bajracharya, Joel Ossher, Ricardo Santos Morla, Pierre F. Baldi, Cristina Videira Lopes (UC Irvine), Paulo Cesar Masiero (Universidade de São Paulo)

**Inti Paper**
Paper ini memperkenalkan sebuah alat bernama **CodeGenie** yang bertujuan untuk mempercepat pembuatan program. Biasanya, pengembang harus menulis kode sendiri setelah merancang tes (*Test-Driven Development*). CodeGenie mengubah alur ini: pengembang cukup membuat tes untuk fitur yang diinginkan, lalu CodeGenie akan mencari kode yang sudah jadi di internet yang cocok dengan tes tersebut. Hebatnya, alat ini tidak hanya mencari, tapi juga otomatis "menjahit" (*weaving*) kode hasil pencarian ke dalam proyek pengembang dan menjalankannya untuk memastikan kode itu benar-benar bekerja sesuai tes. Jika hasilnya memuaskan, pengembang bisa langsung menggunakannya tanpa harus menulis dari nol.



**Bedah Abstrak Mendetail**
1. **"We present CodeGenie, a tool that implements a test-driven approach to search and reuse of code available on large-scale code repositories."**
   - *Maksud:* Peneliti memperkenalkan CodeGenie, sebuah alat yang menggunakan metode berbasis pengujian untuk mencari dan memakai kembali kode dari gudang kode (repositori) skala besar.
2. **"While using CodeGenie developers design test cases for a desired feature first, similar to Test-driven Development (TDD)."**
   - *Maksud:* Saat memakai alat ini, pemrogram merancang skenario pengujian terlebih dahulu untuk fitur yang mau dibuat, mirip dengan cara kerja TDD.
3. **"However, instead of implementing the feature as in TDD, CodeGenie automatically searches for it based on information available in the tests."**
   - *Maksud:* Bedanya dengan TDD biasa, alih-alih pemrogram mengetik kode fiturnya sendiri, CodeGenie yang akan mencari kode tersebut secara otomatis berdasarkan detail yang tertulis di dalam tes.
4. **"To check the suitability of the candidate results in the local context, each result is automatically woven into the developer's project and tested using the original tests."**
   - *Maksud:* Untuk memastikan kode temuan itu pas, sistem akan secara otomatis memasang kode tersebut ke proyek pengguna dan mengujinya langsung menggunakan tes yang sudah dibuat tadi.
5. **"The developer can then reuse the most suitable result."**
   - *Maksud:* Pemrogram tinggal memilih dan memakai hasil pencarian yang paling sukses melewati pengujian.
6. **"Later, reused code can also be unwoven from the project as wished."**
   - *Maksud:* Kode yang sudah dipakai tersebut juga bisa dilepaskan atau dihapus kembali dari proyek dengan mudah jika diinginkan.
7. **"For the code searching and wrapping facilities, CodeGenie relies on Sourcerer, an Internet-scale source code infrastructure that we have developed."**
   - *Maksud:* Untuk urusan mencari dan mengemas kode, CodeGenie menggunakan teknologi Sourcerer, sebuah infrastruktur pencarian kode internet yang telah dikembangkan oleh tim peneliti ini sebelumnya.

**Baseline**
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai baseline infrastruktur pencarian kode berbasis struktur yang menyediakan kemampuan pengindeksan kode skala internet untuk mendukung fitur *search-and-wrap* pada CodeGenie.
* **TDD by Example (Beck, 2003):** Digunakan sebagai baseline metodologi pengembangan perangkat lunak (Test-Driven Development) yang diadaptasi dari penulisan kode manual menjadi penemuan kode berbasis pencarian otomatis.
* **Manual Code Reuse (Standard Practice):** Digunakan sebagai pembanding untuk menunjukkan efisiensi penggunaan alat otomatis dibandingkan proses manual mencari, mengunduh, dan menyesuaikan kode dari web.

**Keyword**
Source code reuse, Source code search, Test-driven development (TDD), CodeGenie, Sourcerer, Automatic testing.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini sangat krusial bagi riset Anda karena CodeGenie adalah pelopor dalam konsep **"Search-driven Development"**. Jika riset Anda membahas tentang otomatisasi pencarian kode yang memiliki jaminan kualitas (melalui eksekusi tes), paper ini memberikan fondasi kuat. Ini melampaui pencarian teks biasa dan masuk ke ranah pencarian fungsional yang sangat relevan dengan tren AI *coding assistant* masa kini.

**Perbedaan dengan Paper Sebelumnya**
1. **Validasi Hasil:** Berbeda dengan paper **Sourcerer (2006)** yang hanya mencari berdasarkan kemiripan struktur, CodeGenie melakukan validasi **dinamis** (menjalankan kode) untuk memastikan hasil pencarian benar-benar berfungsi.
2. **Kueri Spesifik:** Jika paper **PARSEWeb (2007)** menggunakan kueri berupa transformasi objek (A ke B), CodeGenie menggunakan **unit test** lengkap sebagai kueri untuk mencari implementasi fungsional.
3. **Fokus Alur Kerja:** Dibandingkan dengan **RiSE Search (2006)** yang lebih fokus pada persyaratan sistem pencarian umum, CodeGenie fokus pada integrasi pencarian ke dalam siklus **pengembangan (development cycle)** pengembang.
