# Pointcut-QBE (Cisternino & Vaucouleur, 2009)

*Penelitian ini merumuskan bahasa pointcut tertanam menggunakan paradigma code query by example (QBE) untuk mengekstraksi join points pada granularitas tingkat instruksi di dalam tubuh metode tanpa mendegradasi prinsip obliviousness pada pemrograman berorientasi aspek.*

**Judul**
Aspect oriented programming made easy: An embedded pointcut language, 16th Asia-Pacific Software Engineering Conference (APSEC 2009), IEEE, 2009

**Penulis**
Antonio Cisternino (Università di Pisa), Sebastien Vaucouleur (IT-Universitetet i København)

**Inti Paper**
Paper ini membahas cara mempermudah penggunaan Pemrograman Berorientasi Aspek (*Aspect-Oriented Programming* atau AOP). AOP adalah teknik di mana kita bisa menyisipkan fungsi tambahan (seperti pencatatan log atau keamanan) ke dalam kode utama tanpa mengubah kode tersebut secara langsung. Masalahnya, cara menentukan "di mana" fungsi itu harus disisipkan (disebut *pointcut*) biasanya sangat sulit dipelajari. Peneliti mengusulkan bahasa baru berbasis **Code Query by Example (QBE)**. Alih-alih menulis kode pencarian yang rumit, pemrogram cukup memberikan "contoh" potongan kode yang ingin mereka cari, dan sistem akan menemukannya secara otomatis di lokasi mana pun dalam program. Alat ini dibuat menyatu dengan bahasa pemrograman umum untuk memudahkan kerja pengembang.



**Bedah Abstrak Mendetail**
1. **"An important challenge with respect to aspect-oriented programming is to make this technology easier to use, so that it becomes accessible to a larger number of developers."**
   - *Maksud:* Tantangan besar dalam pemrograman berorientasi aspek (AOP) adalah membuatnya lebih mudah dipakai agar bisa digunakan oleh lebih banyak pengembang.
2. **"We address this challenge with a new pointcut language based on the concept of code query by example."**
   - *Maksud:* Peneliti menjawab tantangan tersebut dengan menciptakan bahasa penentu lokasi (*pointcut*) baru yang menggunakan konsep mencari kode melalui pemberian contoh (*query by example*).
3. **"Our framework can be used to denote code patterns, which are difficult to express using traditional join point languages."**
   - *Maksud:* Kerangka kerja ini bisa digunakan untuk menandai pola kode yang biasanya sangat sulit dituliskan jika menggunakan bahasa pencarian tradisional.
4. **"A further benefit of our approach is that it can be used to denote join points at almost arbitrary locations inside method bodies - without sacrificing obliviousness."**
   - *Maksud:* Keuntungan lainnya adalah sistem ini bisa menemukan titik penyisipan kode di posisi mana pun di dalam fungsi, tanpa harus merusak prinsip dasar AOP (di mana kode utama tidak perlu tahu ada kode tambahan yang masuk).
5. **"Finally, a particularity of our pointcut language is that it is embedded in a general purpose language."**
   - *Maksud:* Keunikan bahasa ini adalah ia tertanam langsung di dalam bahasa pemrograman umum yang biasa dipakai sehari-hari.
6. **"We outline the benefits, and limitations of our framework, and we summarize the implementation of a prototype."**
   - *Maksud:* Peneliti merinci kelebihan dan kekurangan sistem mereka, serta meringkas cara pembuatan model purwarupanya.

**Baseline**
* **AspectJ (Standard AOP Framework):** Digunakan sebagai baseline bahasa *pointcut* tradisional untuk membandingkan fleksibilitas dalam menentukan *join points* di dalam *method body*.
* **CLI - Common Language Infrastructure (ECMA, 2006):** Digunakan sebagai baseline infrastruktur eksekusi kode untuk implementasi sistem pada lingkungan .NET/C#.
* **Parnas (Parnas, 1972):** Digunakan sebagai acuan teoretis mengenai dekomposisi sistem menjadi modul-modul independen yang mendasari filosofi pemisahan perhatian (*separation of concerns*).
* **Vaucouleur (Vaucouleur, 2009):** Digunakan sebagai baseline penelitian sebelumnya mengenai sistem yang dapat disesuaikan tanpa mengasumsi pengetahuan penuh tentang struktur internal kode.

**Keyword**
Aspect-Oriented Programming (AOP), Code query by example, Pointcut language, Join point, Pattern matching.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Query-by-Example).**
Paper ini sangat relevan jika riset "Code Search" Anda mengeksplorasi **metode kueri alternatif**. Kebanyakan mesin pencari kode menggunakan teks atau bahasa alami, tetapi paper ini menggunakan **potongan kode sebagai kueri** (*Query by Example*). Jika riset Anda membahas tentang bagaimana menemukan potongan kode yang mirip berdasarkan struktur atau contoh kode yang diberikan pengguna (bukan kata kunci), maka paper ini memberikan landasan teori yang sangat kuat tentang efektivitas metode QBE dalam mencari pola di dalam basis kode yang besar.

**Perbedaan dengan Paper Sebelumnya**
1. **Model Kueri:** Berbeda dengan paper **SNIFF (2009)** yang kuerinya bahasa Inggris, paper ini menggunakan **potongan kode nyata** sebagai kueri untuk mencari lokasi serupa.
2. **Granularitas:** Jika paper **Sourcerer (2009)** mencari level file atau proyek, paper ini mencari hingga level **instruksi di dalam tubuh fungsi** (*method body*).
3. **Penerapan:** Berbeda dengan **CodeGenie (2009)** yang mencari kode untuk dipakai ulang (*reuse*), paper ini melakukan pencarian kode untuk **penyisipan logika baru** (aspek) secara otomatis.
