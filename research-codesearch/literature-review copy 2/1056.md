# Code Conjurer (Janjic et al., 2009)

*Makalah posisi ini mengusulkan integrasi plug-in Eclipse 'Code Conjurer' dengan mesin pencari 'merobase' untuk memfasilitasi temu kembali komponen perangkat lunak melalui paradigma test-driven search guna mereduksi beban kognitif dalam verifikasi fungsionalitas komponen reuse.*

**Judul**
Lowering the barrier to reuse through test-driven search, 2009 ICSE Workshop on Search-Driven Development - Users, Infrastructure, Tools and Evaluation (SUITE 2009), IEEE Computer Society, 2009

**Penulis**
Werner Janjic, Dietmar Stoll, Philipp Bostan, Colin Atkinson (Universität Mannheim, Jerman)

**Inti Paper**
Paper ini membahas cara mempermudah pemrogram dalam menggunakan kembali (*reuse*) kode yang sudah ada di internet atau repositori perusahaan. Masalah utama saat ini adalah meskipun mesin pencari kode sudah canggih, pemrogram masih harus bekerja keras untuk memeriksa dan menguji apakah kode yang ditemukan benar-benar cocok dan berfungsi dengan baik. Peneliti mengusulkan visi di mana pencarian kode dilakukan melalui pengujian (*test-driven search*). Mereka memperkenalkan alat bernama **Code Conjurer**, sebuah *plugin* untuk aplikasi pengodingan (Eclipse), yang bekerja sama dengan mesin pencari **merobase**. Alat ini memungkinkan pencarian kode terjadi secara otomatis di latar belakang saat pemrogram sedang menulis kode, sehingga meningkatkan kualitas hasil pencarian tanpa mengganggu konsentrasi pemrogram.



**Bedah Abstrak Mendetail**
1. **"Dedicated software search engines that index open source software repositories or in-house software assets significantly enhance the chance of finding software components suitable for reuse."**
   - *Maksud:* Mesin pencari khusus yang mencatat kode sumber terbuka atau aset internal perusahaan sangat membantu meningkatkan peluang menemukan komponen perangkat lunak yang bisa dipakai kembali.
2. **"However, they still leave the work of evaluating and testing components to the developer."**
   - *Maksud:* Namun, mesin pencari tersebut masih membebankan pekerjaan evaluasi dan pengujian komponen tersebut kepada pengembang itu sendiri.
3. **"To significantly change the risk/cost/benefit tradeoff involved in software reuse, search engines need to be supported by user friendly environments that deliver code search functionality, non-intrusively, right to developers' fingertips during key software development activities and significantly raise the quality of search results."**
   - *Maksud:* Untuk mengubah keseimbangan antara risiko, biaya, dan manfaat dalam pemakaian kembali kode, mesin pencari harus didukung oleh lingkungan kerja yang ramah pengguna, tidak mengganggu, tersedia langsung saat pengembang bekerja, dan mampu meningkatkan kualitas hasil pencarian secara drastis.
4. **"In this position paper we describe our attempt to realize this vision through an Eclipse plugin, Code Conjurer, in tandem with the code search engine, merobase."**
   - *Maksud:* Dalam makalah ini, peneliti menjelaskan upaya mereka mewujudkan visi tersebut melalui alat tambahan Eclipse bernama Code Conjurer yang bekerja sama dengan mesin pencari merobase.

**Baseline**
* **CodeGenie (Lemos et al., 2007):** Digunakan sebagai baseline untuk alat pencarian kode sumber berbasis pengujian (*test-driven*) yang mengintegrasikan pencarian ke dalam siklus pengembangan.
* **Hummel's Extreme Harvesting (Hummel et al., 2007):** Digunakan sebagai baseline metodologi pengambilan komponen secara agresif dari repositori untuk mendukung pengembangan tangkas (*agile*).
* **Rascal (McCarey et al., 2005):** Digunakan sebagai baseline agen pemberi rekomendasi komponen untuk penggunaan kembali kode pada lingkungan pengembangan tangkas.
* **Approximate Structural Matching (Holmes & Murphy, 2006):** Digunakan sebagai baseline teknik pencocokan struktur kode untuk merekomendasikan contoh kode yang relevan berdasarkan konteks pengembang.

**Keyword**
Code search, Software reuse, Test-driven search, Eclipse plugin, merobase, Component retrieval.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini sangat relevan karena berfokus pada **integrasi pencarian kode ke dalam alur kerja pengembang** (IDE-based search). Jika riset Anda membahas tentang bagaimana membuat pencarian kode menjadi otomatis atau berbasis pengujian (*test-driven*), paper ini memberikan landasan filosofis dan teknis tentang pengurangan hambatan (*lowering barrier*) dalam penggunaan kembali kode. Ini melengkapi riset Anda dari sisi "efisiensi proses pencarian".

**Perbedaan dengan Paper Sebelumnya**
1. **Mekanisme Pencarian:** Berbeda dengan paper **SNIFF (2009)** yang menggunakan kueri bahasa alami, Code Conjurer menggunakan **spesifikasi teknis dan pengujian** sebagai kueri untuk memastikan fungsionalitas.
2. **Lingkungan Kerja:** Jika paper **Sourcerer (2009)** lebih fokus pada infrastruktur web/server, paper ini fokus pada **sisi klien (IDE plugin)** agar pengembang tidak perlu berpindah aplikasi saat mencari kode.
3. **Fokus Validasi:** Dibandingkan dengan **MAPO (2009)** yang mencari pola API, Code Conjurer mencari **komponen fungsional utuh** yang dapat langsung divalidasi dengan unit test.
