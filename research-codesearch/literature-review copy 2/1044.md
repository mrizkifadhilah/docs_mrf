# Sourcerer (Linstead et al., 2009)

*Penelitian ini mengintegrasikan pemodelan topik probabilistik Latent Dirichlet Allocation (LDA) dan Author-Topic (AT) dengan algoritma CodeRank berbasis graf untuk mengekstraksi relasi semantik dan struktural pada repositori kode sumber skala internet.*

**Judul**
Sourcerer: Mining and searching internet-scale software repositories, Data Mining and Knowledge Discovery, Springer, 2009

**Penulis**
Erik J. Linstead, Sushil Krishna Bajracharya, Trung Chi Ngo, Paul Rigor, Cristina Videira Lopes, Pierre F. Baldi (University of California, Irvine, Amerika Serikat)

**Inti Paper**
Paper ini memperkenalkan **Sourcerer**, sebuah infrastruktur raksasa yang dirancang untuk mengumpulkan (*crawling*), membedah (*parsing*), dan menyimpan jutaan baris kode dari internet secara otomatis. Peneliti melakukan eksperimen besar dengan mengumpulkan lebih dari 38 juta baris kode Java. Mereka tidak hanya mencari kode berdasarkan kata kunci, tetapi menggunakan model matematika canggih untuk menemukan "topik" tersembunyi di dalam kode dan menghubungkannya dengan keahlian pengembangnya. Keunggulan utamanya adalah penggabungan antara teks kode dengan informasi struktur (hubungan antar kode) menggunakan metode **CodeRank**. Hasilnya, mesin ini mampu menemukan kode yang jauh lebih akurat (meningkat hingga 30%) dibandingkan pencarian yang hanya mengandalkan teks biasa.



**Bedah Abstrak Mendetail**
1. **"Large repositories of source code available over the Internet, or within large organizations, create new challenges and opportunities for data mining and statistical machine learning."**
   - *Maksud:* Kumpulan kode yang sangat besar di internet atau perusahaan besar memberikan tantangan sekaligus peluang baru untuk diolah menggunakan teknik penambangan data dan kecerdasan buatan.
2. **"Here we first develop Sourcerer, an infrastructure for the automated crawling, parsing, fingerprinting, and database storage of open source software on an Internet-scale."**
   - *Maksud:* Peneliti membangun Sourcerer, sebuah sistem lengkap untuk mengambil, membaca, menandai, dan menyimpan kode sumber terbuka dari seluruh internet secara otomatis.
3. **"Simple statistical analyses of the data first reveal robust power-law behavior for package, method call, and lexical containment distributions."**
   - *Maksud:* Analisis awal menunjukkan adanya pola keteraturan statistik (power-law) pada cara pengembang menyusun paket kode dan memanggil fungsi.
4. **"We then develop and apply unsupervised, probabilistic, topic and author-topic (AT) models to automatically discover the topics embedded in the code..."**
   - *Maksud:* Peneliti menggunakan model cerdas untuk secara otomatis mengenali topik atau tema apa saja yang ada di dalam kode tanpa perlu diberitahu manual.
5. **"In addition to serving as a convenient summary... these and other related distributions provide a statistical... basis for quantifying and analyzing source file similarity, developer similarity and competence..."**
   - *Maksud:* Data ini tidak hanya merangkum fungsi program, tetapi juga menjadi dasar ilmiah untuk mengukur kemiripan antar file kode serta keahlian seorang pengembang.
6. **"Finally, by combining software textual content with structural information captured by our CodeRank approach, we are able to significantly improve software retrieval performance..."**
   - *Maksud:* Terakhir, dengan menggabungkan teks kode dan informasi hubungan antar kode (CodeRank), sistem ini berhasil meningkatkan performa pencarian kode secara signifikan.
7. **"...increasing the area under the curve (AUC) retrieval metric to 0.92- roughly 10-30% better than previous approaches based on text alone."**
   - *Maksud:* Akurasi pencarian mencapai nilai 0.92, yang artinya 10% hingga 30% lebih hebat daripada cara pencarian lama yang hanya mencari berdasarkan kata kunci teks.

**Baseline**
* **Text-only Retrieval (Baeza-Yates & Ribeiro-Neto, 1999):** Digunakan sebagai baseline Information Retrieval tradisional berbasis teks murni (seperti model vektor ruang) untuk menunjukkan bahwa pencarian kode membutuhkan lebih dari sekadar kata kunci teks.
* **Bug Fixer Recommendation (Anvik et al., 2006):** Digunakan sebagai baseline pembanding untuk analisis aktivitas pengembang dan penugasan staf berdasarkan konten teknis.
* **PageRank-based Code Search (Standard Graph Approaches):** Digunakan sebagai dasar perbandingan untuk algoritma **CodeRank** dalam mengukur tingkat kepentingan sebuah kelas atau metode berdasarkan hubungan dependensinya.

**Keyword**
Code search, Code retrieval, Mining software repositories, Author-topic modeling, CodeRank, Program understanding.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Must-Read).**
Paper ini adalah salah satu "kitab suci" dalam riset Code Search modern. Jika riset Anda menggunakan istilah **"Structural Code Search"** atau mengombinasikan **"Information Retrieval"** dengan **"Graph Analysis"**, Sourcerer adalah fondasinya. Paper ini memberikan kerangka kerja lengkap dari pengambilan data hingga pemeringkatan hasil yang sangat valid untuk dikutip dalam riset Anda.

**Perbedaan dengan Paper Sebelumnya**
1. **Skala Data:** Berbeda dengan paper **Sourcerer (2006)** versi awal yang masih berupa ide/prototipe kecil, paper tahun 2009 ini menyajikan evaluasi **skala internet** dengan 4.632 proyek nyata.
2. **Kombinasi Teknik:** Jika paper **LDA Bug Localization (2008)** hanya menggunakan topik teks, Sourcerer menggabungkan **Topik Teks + Struktur Graf (CodeRank)**.
3. **Analisis Penulis:** Berbeda dengan **Koders Log Analysis (2009)** yang fokus pada apa yang dicari pengguna, Sourcerer fokus pada **siapa yang menulis kode** (Author-Topic) untuk menentukan kompetensi pengembang dalam hasil pencarian.
