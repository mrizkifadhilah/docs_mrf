# S6-Demo (Reiss, 2009)

*Penelitian ini mendemonstrasikan sistem S6 yang mengintegrasikan mekanisme penelusuran kode berbasis spesifikasi formal dengan engine transformasi program untuk meregenerasi artefak perangkat lunak yang secara semantik ekuivalen dengan kebutuhan fungsional pengguna.*

**Judul**
Semantics-based code search demonstration proposal, 2009 IEEE International Conference on Software Maintenance (ICSM), IEEE, 2009

**Penulis**
Steven P. Reiss (Brown University, Providence, Amerika Serikat)

**Inti Paper**
Paper ini merupakan proposal demonstrasi untuk sistem **S6**, sebuah alat pencari kode revolusioner yang tidak hanya mencari teks, tetapi memahami maksud (semantik) dari pemrogram. Masalah yang ingin diselesaikan adalah sulitnya menemukan kode yang "siap pakai" karena sering kali kode yang tersedia di internet sedikit berbeda dengan kebutuhan kita (misalnya beda nama variabel atau urutan parameter). Sistem ini memungkinkan pemrogram memberikan instruksi detail (spesifikasi) melalui web, seperti nama fungsi, contoh pengujian (*test cases*), hingga batasan keamanan. S6 kemudian mencari kode yang paling mirip di repositori sumber terbuka dan secara otomatis **mengubahnya** (transformasi) agar sesuai persis dengan permintaan pemrogram.



**Bedah Abstrak Mendetail**
1. **"Our goal is to use the vast repositories of available open source code to generate specific functions or classes that meet a user's specifications."**
   - *Maksud:* Tujuan peneliti adalah memanfaatkan gudang kode sumber terbuka yang sangat luas untuk menciptakan fungsi atau kelas tertentu yang memenuhi instruksi detail dari pengguna.
2. **"The key words here are specifications and generate."**
   - *Maksud:* Fokus utama dalam alat ini adalah pada "spesifikasi" (permintaan detail pengguna) dan "generasi" (menghasilkan kode yang benar-benar pas).
3. **"We let users specify what they are looking for as precisely as possible using keywords, class or method signatures, test cases, contracts, and security constraints using a simple, web-based interface."**
   - *Maksud:* Peneliti membiarkan pengguna menjelaskan apa yang mereka cari sedetail mungkin melalui web, mulai dari kata kunci, bentuk fungsi, tes otomatis, aturan logika, hingga batasan keamanan.
4. **"Our system then uses an open set of program transformations to map retrieved code into what the user asked for."**
   - *Maksud:* Sistem kemudian menggunakan serangkaian aturan perubahan program untuk memodifikasi kode yang ditemukan agar cocok dengan permintaan yang diberikan pengguna.
5. **"This approach is implemented in a prototype system for Java with a web interface."**
   - *Maksud:* Metode ini sudah diterapkan dalam bentuk model contoh (purwarupa) untuk bahasa Java yang bisa diakses lewat browser.

**Baseline**
* **Sourcerer (Bajracharya et al., 2006):** Digunakan sebagai baseline infrastruktur pencarian kode berbasis struktur untuk menunjukkan bahwa S6 melampaui pencarian struktural dengan menambahkan lapisan transformasi.
* **PARSEWeb (Thummalapenta & Xie, 2007):** Digunakan sebagai baseline alat bantu pencarian kode yang menyarankan urutan pemanggilan API untuk membandingkan efektivitas dalam menghasilkan kode yang fungsional.
* **CodeGenie (Lemos et al., 2007):** Digunakan sebagai baseline sistem pencarian berbasis *test-case* untuk membedakan kemampuan S6 dalam melakukan transformasi kode, bukan sekadar pencarian.
* **Assieme (Hoffmann et al., 2007):** Digunakan sebagai baseline antarmuka pencarian web bagi pengembang untuk membandingkan pengalaman pengguna dalam mengeksplorasi hasil pencarian.

**Keyword**
Semantics-based search, Program transformations, Test-driven search, Java code search, Specification-based retrieval.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Penting untuk Bab Demonstrasi/Implementasi).**
Paper ini sangat relevan sebagai bukti implementasi nyata dari konsep **Semantics-based Code Search**. Jika riset Anda membahas tentang masa depan mesin pencari kode yang tidak hanya "menemukan" tapi juga "menyesuaikan" kode untuk pengguna, paper ini adalah rujukan utamanya. Paper ini memperkuat argumen riset Anda bahwa pencarian kode di masa depan akan sangat bergantung pada spesifikasi formal seperti *unit test*.

**Perbedaan dengan Paper Sebelumnya**
1. **Sifat Makalah:** Berbeda dengan paper **S6 (Reiss, 2009 - ICSE)** yang fokus pada teori dan algoritma transformasi, paper ini fokus pada **demonstrasi sistem** dan penggunaan antarmuka webnya.
2. **Interaksi Pengguna:** Paper ini lebih menekankan pada kemudahan **web-based interface** bagi pemrogram untuk memasukkan berbagai kendala (*constraints*) secara praktis.
3. **Fokus Maintenance:** Karena dipublikasikan di konferensi *Software Maintenance*, paper ini menekankan bagaimana sistem S6 dapat membantu dalam **perbaikan kode** dengan mencari komponen pengganti yang sudah teruji secara otomatis.
