# JavaBeans Search (Washizaki & Fukazawa, 2004)

*Sistem ini mengimplementasikan ekstraksi entitas perangkat lunak dari source code Java melalui analisis keterhubungan kelas untuk menghasilkan komponen JavaBeans yang dapat digunakan kembali secara mandiri serta diindeks berdasarkan metadata fungsional.*

**Judul**
A search system for java programs by using extracted JavaBeans components, 19th Annual ACM Conference on Object-Oriented Programming, Systems, Languages, and Applications (OOPSLA'04), ACM, 2004

**Penulis**
Hironori Washizaki (National Institute of Informatics, Tokyo), Yoshiaoki Fukazawa (Waseda University, Tokyo)

**Inti Paper**
Paper ini memperkenalkan sistem pencarian kode yang unik karena tidak hanya mencari potongan teks kode, tetapi mampu mengekstrak "komponen" fungsional yang sudah jadi. Sistem ini menganalisis hubungan antar kelas dalam program Java yang sudah ada, lalu membungkus kelas-kelas yang saling berkaitan tersebut menjadi komponen JavaBeans. Komponen-komponen ini kemudian diberikan label (indeks) secara otomatis berdasarkan komentar dan nama tipe data di dalamnya. Tujuannya adalah agar pengembang bisa mencari solusi perangkat lunak melalui peramban web dan langsung mendapatkan komponen yang siap pakai, sehingga proses pengembangan menjadi jauh lebih cepat dibandingkan menulis kode dari nol.



**Baseline**
* **Agora (Seacord, 1998):** Digunakan sebagai baseline mesin pencari komponen perangkat lunak berbasis web yang mengumpulkan informasi komponen melalui agen pencari otomatis.
* **JavaBeans 1.01 Specification (Sun Microsystems, 1997):** Digunakan sebagai baseline standar arsitektur komponen Java untuk memastikan bahwa kode yang diekstrak oleh sistem mematuhi protokol komponen yang dapat digunakan kembali secara mandiri.
* **CodeBroker (Ye, 2002):** Digunakan sebagai baseline sistem pendukung pengembangan yang melakukan pencarian otomatis di latar belakang untuk memberikan saran penggunaan kembali kode kepada programmer.
* **Reusability Metrics Suite (Washizaki, 2003):** Digunakan sebagai dasar pengukuran untuk menilai apakah komponen yang diekstrak oleh sistem pencarian ini benar-benar layak dan cukup mandiri untuk digunakan kembali.

**Keyword**
JavaBeans, Component extraction, Program search, Software reusability, Object-oriented programming, JavaBeans components.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini sangat krusial bagi riset Anda karena membahas **unit pencarian yang cerdas**. Kebanyakan sistem pencarian kode hanya mencari baris teks (keyword), tetapi paper ini menawarkan pencarian berbasis **unit fungsional (komponen)**. Konsep analisis dependensi kelas untuk mengekstrak komponen yang "siap pakai" adalah fondasi penting dalam riset *Semantic Code Search* dan *Software Reuse*. Ini akan memberikan argumen kuat pada riset Anda mengenai pentingnya memahami struktur kode, bukan sekadar kata kunci dalam teks.

**Perbedaan dengan Paper Sebelumnya**
1. **Target Spesifik:** Berbeda dengan paper **Component Search (LNCS, 2004)** sebelumnya yang lebih bersifat umum, paper OOPSLA ini secara spesifik mengoptimalkan sistem untuk menghasilkan komponen dengan standar **JavaBeans**.
2. **Konteks Publikasi:** Publikasi di OOPSLA (ACM) menekankan pada aspek sistem dan bahasa pemrograman yang lebih mendalam dibandingkan versi jurnal atau workshop lainnya.
3. **Fokus Implementasi:** Jika paper **Incremental Change (Rajlich & Gosavi, 2004)** fokus pada pencarian untuk pemeliharaan kode lama, paper Washizaki ini fokus pada pencarian untuk **membangun aplikasi baru** melalui perakitan komponen yang sudah ada.
