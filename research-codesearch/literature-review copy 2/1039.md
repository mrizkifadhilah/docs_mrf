# SpotWeb (Thummalapenta & Xie, 2008)

*Sistem ini mengintegrasikan mesin pencari kode untuk melakukan penambangan repositori open source berskala internet guna mengidentifikasi titik krusial (hotspots) dan titik marjinal (coldspots) pada antarmuka pemrograman aplikasi (API) melalui analisis frekuensi instansiasi.*

**Judul**
SpotWeb: Detecting framework hotspots and coldspots via mining open source code on the web, 23rd IEEE/ACM International Conference on Automated Software Engineering (ASE 2008), IEEE Computer Society/ACM, 2008

**Penulis**
Suresh Thummalapenta, Tao Xie (North Carolina State University, Amerika Serikat)

**Inti Paper**
Paper ini membahas cara membantu pengembang perangkat lunak agar lebih mudah memahami cara menggunakan *framework* atau *library* baru (seperti Java API) yang seringkali sangat rumit dan dokumentasinya kurang memadai. Peneliti menciptakan alat bernama **SpotWeb** yang bekerja seperti detektif kode. SpotWeb menggunakan mesin pencari kode di internet untuk mengumpulkan ribuan contoh penggunaan kode asli. Dari situ, SpotWeb menentukan dua hal: **Hotspots** (bagian kode yang sangat populer dan sering dipakai orang lain, sehingga aman untuk dipelajari pemula) dan **Coldspots** (bagian kode yang sangat jarang dipakai, yang menandakan bahwa bagian tersebut sulit ditemukan contohnya atau mungkin bermasalah). Informasi ini membantu pengembang tahu harus mulai belajar dari mana dan bagian mana yang harus diwaspadai.



**Bedah Abstrak Mendetail**
1. **"Software developers often face challenges in reusing open source frameworks due to several factors such as the framework complexity and lack of proper documentation."**
   - *Maksud:* Pengembang sering kesulitan memakai ulang *framework* gratisan karena rumitnya struktur dan minimnya buku panduan yang jelas.
2. **"In this paper, we propose a code-search-engine-based approach that detects hotspots in a given framework by mining code examples gathered from open source repositories available on the web..."**
   - *Maksud:* Peneliti menawarkan solusi berbasis mesin pencari kode yang bisa mendeteksi "titik panas" (*hotspots*) dengan cara menambang contoh kode dari berbagai tempat penyimpanan kode di internet.
3. **"...these hotspots are API classes and methods that are frequently reused."**
   - *Maksud:* Titik panas ini adalah bagian-bagian perintah program (kelas dan metode) yang terdeteksi paling sering digunakan berulang kali oleh orang banyak.
4. **"Hotspots can serve as starting points for developers in understanding and reusing the given framework."**
   - *Maksud:* Bagian populer ini bisa menjadi panduan atau titik awal bagi pengembang untuk memahami cara kerja *framework* tersebut.
5. **"Our approach also detects coldspots, which are API classes and methods that are rarely used."**
   - *Maksud:* Selain titik panas, sistem ini juga bisa mendeteksi "titik dingin" (*coldspots*), yaitu bagian kode yang sangat jarang disentuh atau digunakan.
6. **"Coldspots serve as caveats for developers as there can be difficulties in finding relevant code examples and are generally less exercised compared to hotspots."**
   - *Maksud:* Titik dingin ini menjadi peringatan bagi pengembang karena akan susah mencari contoh kodenya dan biasanya kurang teruji kekuatannya dibandingkan bagian yang populer.
7. **"We developed a tool, called SpotWeb, for frameworks or libraries written in Java and used our tool to detect hotspots and coldspots of eight widely used open source frameworks."**
   - *Maksud:* Peneliti membuat aplikasi bernama SpotWeb untuk bahasa Java dan memakainya untuk membedah delapan *framework* populer di dunia.
8. **"We show the utility of our detected hotspots by comparing these hotspots with the API classes reused by a real application and compare our results with the results of a previous related approach."**
   - *Maksud:* Peneliti membuktikan kegunaan alat ini dengan mencocokkan hasil temuan mereka dengan penggunaan di aplikasi nyata dan membandingkannya dengan metode lama.

**Baseline**
* **MAPO (Xie & Pei, 2006):** Digunakan sebagai baseline untuk metode penambangan pola penggunaan API (*API usage patterns*) melalui teknik *frequent itemset mining* pada repositori kode.
* **PARSEWeb (Thummalapenta & Xie, 2007):** Digunakan sebagai baseline sistem asisten pengembang yang menyarankan urutan pemanggilan metode (*method sequences*) berdasarkan hasil pencarian kode.
* **Reverse Engineering Framework Reuse Interfaces (Viljamaa, 2003):** Digunakan sebagai baseline pendekatan untuk memahami antarmuka penggunaan kembali *framework* melalui teknik *formal concept analysis*.

**Keyword**
Code search engine, Hotspots, Coldspots, API mining, Open source repositories, Software reusability.

**Kelayakan Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini wajib masuk ke riset Anda karena membahas aspek **pasca-pencarian (post-search analysis)**. Jika riset utama Anda adalah pencarian kode, paper ini memberikan wawasan tentang bagaimana hasil pencarian yang masif bisa diolah untuk memberikan nilai tambah (berupa rekomendasi *hotspots*). Ini membantu Anda menjelaskan strategi pemeringkatan (*ranking*) hasil pencarian kode berdasarkan utilitas praktisnya di komunitas pengembang.

**Perbedaan dengan Paper Sebelumnya**
1. **Konsep Coldspots:** Berbeda dengan paper **SpotWeb (ICSE 2008)** versi awal yang hanya fokus pada titik panas, paper versi **ASE 2008** ini memperkenalkan konsep **Coldspots** (bagian yang jarang digunakan) sebagai fitur baru untuk memperingatkan pengembang.
2. **Skala Evaluasi:** Paper ini melakukan evaluasi yang lebih luas pada **delapan framework** besar, dibandingkan versi sebelumnya yang hanya berfokus pada Log4j dan JUnit.
3. **Metode Validasi:** Jika paper **CodeGenie (2007)** melakukan validasi melalui eksekusi tes, SpotWeb memvalidasi hasilnya dengan membandingkannya terhadap pola penggunaan di **aplikasi dunia nyata** untuk melihat apakah titik panas yang dideteksi memang benar-benar digunakan secara intensif oleh praktisi.
