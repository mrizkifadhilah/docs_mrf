# Reference Vectors (Ohno & Murao, 2007)

*Penelitian ini merumuskan metodologi kalkulasi similaritas kode sumber melalui ekstraksi fitur tekstural dari token-cooccurrence matrices yang direpresentasikan ke dalam bentuk vektor referensi untuk mereduksi latensi komputasi dan okupansi ruang penyimpanan pada sistem temu kembali.*

**Judul**
Measuring source code similarity using reference vectors, International Journal of Innovative Computing, Information and Control, ICIC International, 2007

**Penulis**
Asako Ohno, Hajime Murao (Kobe University, Jepang)

**Inti Paper**
Paper ini mengusulkan cara baru yang sangat cepat untuk membandingkan kemiripan antara dua kode program. Jika cara lama biasanya membandingkan teks kode secara langsung (yang memakan waktu dan memori besar), metode ini mengubah kode program menjadi angka-angka statistik yang disebut "vektor referensi". Angka-angka ini diambil dari pola seberapa sering kata-kata tertentu muncul bersamaan dalam kode (*token-cooccurrence*). Karena perbandingannya hanya berupa jarak antar vektor (matematika sederhana), proses pencarian kode menjadi jauh lebih singkat dan sistem tidak perlu menyimpan file kode asli yang besar di database. Peneliti menguji metode ini pada tugas-tugas pemrograman mahasiswa dan terbukti efektif menemukan kemiripan (atau plagiarisme) dengan waktu yang sangat cepat.



**Bedah Abstrak Mendetail**
1. **"This paper discusses a method for measuring the similarity between program source codes."**
   - *Maksud:* Makalah ini membahas sebuah metode teknis untuk mengukur tingkat kemiripan di antara kode sumber program.
2. **"Unlike many existing methods, our method compares the source codes indirectly using reference vectors instead of using the original source codes."**
   - *Maksud:* Berbeda dengan metode yang sudah ada, cara ini tidak membandingkan teks asli kode secara langsung, melainkan secara tidak langsung melalui perantara vektor angka.
3. **"Elements of the vectors are textural features of token-cooccurrence matrices generated from the source codes."**
   - *Maksud:* Isi dari vektor tersebut adalah ciri-ciri tekstur yang diambil dari tabel frekuensi kemunculan kata kunci kode yang saling berdekatan.
4. **"Since similarity is simply defined as a distance between two reference vectors, it can be calculated in a very short time."**
   - *Maksud:* Karena kemiripan hanya dihitung berdasarkan jarak matematika antara dua titik vektor, prosesnya bisa selesai dalam waktu yang sangat singkat.
5. **"Another advantage is that we do not need to retain a huge storage area for source codes when applying this method to a source code retrieval system."**
   - *Maksud:* Keuntungan lainnya adalah sistem pencarian kode tidak perlu menyediakan ruang penyimpanan raksasa untuk menyimpan file kode sumber aslinya.
6. **"We implemented the proposed method on a simple source code retrieval system and made experiments with Java program source codes submitted as assignments for a programming class."**
   - *Maksud:* Peneliti mencoba metode ini pada sistem pencarian kode sederhana dan mengujinya menggunakan kumpulan tugas pemrograman Java milik mahasiswa.
7. **"Results confirmed that our method can effectively find reasonable similarity between pairs of source codes in a short time."**
   - *Maksud:* Hasil eksperimen mengonfirmasi bahwa metode ini efektif dalam menemukan kemiripan yang akurat dalam waktu singkat.

**Baseline**
* **Dup (Baker, 1995):** Digunakan sebagai baseline untuk algoritma pendeteksian duplikasi kode pada sistem skala besar berbasis pencarian pola baris.
* **CCFinder (Kamiya et al., 2002):** Digunakan sebagai baseline untuk sistem deteksi klon berbasis token (*token-based*) yang bersifat multilinguistik.
* **JPlag (Prechelt et al., 2002):** Digunakan sebagai baseline untuk alat pendeteksi plagiarisme kode yang membandingkan struktur program secara lebih mendalam.
* **YAP3 (Wise, 1996):** Digunakan sebagai baseline untuk deteksi kemiripan teks program yang menggunakan teknik perbandingan *n-grams* atau tokenisasi.
* **AST-based Detection (Baxter et al., 1998):** Digunakan sebagai baseline tandingan untuk metode deteksi kemiripan berbasis struktur pohon (*Abstract Syntax Tree*).

**Keyword**
Source code similarity, Reference vectors, Token-cooccurrence matrix, Source code retrieval, Plagiarism detection.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK.**
Paper ini sangat relevan karena membahas **efisiensi representasi data** dalam mesin pencari kode (*Code Search Engine*). Riset Anda yang berfokus pada "Code Search" akan sangat terbantu oleh konsep "Reference Vectors" ini untuk menjelaskan bagaimana sebuah mesin pencari bisa memberikan hasil yang cepat tanpa harus membebani server dengan penyimpanan file kode yang masif. Ini adalah fondasi penting untuk teknik *Information Retrieval* pada kode sumber.

**Perbedaan dengan Paper Sebelumnya**
1. **Representasi Data:** Berbeda dengan paper **Sourcerer (Bajracharya et al., 2006)** yang menyimpan informasi struktural dalam database relasional yang kompleks, paper ini menggunakan **vektor statistik** yang jauh lebih ringan.
2. **Kecepatan Komputasi:** Jika paper **CodeQuest (Hajiyev et al., 2006)** mengandalkan kueri Datalog untuk mencari hubungan kode, paper ini menggunakan **jarak antar vektor** (Euclidean/Cosine) yang secara komputasi lebih murah.
3. **Fokus Kegunaan:** Dibandingkan dengan **OrcA (2018)** yang melakukan pencarian diferensial untuk mencari bug, paper ini fokus pada **pencarian kemiripan tekstural** untuk aplikasi seperti deteksi plagiarisme atau temu kembali kode yang serupa secara efisien.
