# WYSIWIB (Lawall et al., 2009)

*Penelitian ini merumuskan metodologi deteksi defek pada kernel Linux melalui pendekatan program search berbasis aliran kontrol (control-flow) yang menggunakan spesifikasi deklaratif dengan sintaksis menyerupai bahasa C untuk memetakan protokol API.*

**Judul**
WYSIWIB: A declarative approach to finding API protocols and bugs in linux code, Proceedings of the International Conference on Dependable Systems and Networks (DSN 2009), IEEE, 2009

**Penulis**
Julia L. Lawall, Julien Brunel, Nicolas Palix, René Rydhof Hansen, Henrik Stuart, Gilles Muller (University of Copenhagen, Aalborg University, INRIA, ONERA)

**Inti Paper**
Paper ini membahas cara menemukan kesalahan (*bugs*) pada sistem operasi Linux dengan cara yang lebih mudah bagi pengembang. Peneliti berargumen bahwa alat deteksi *bug* yang ada saat ini terlalu rumit dan sulit disesuaikan dengan kebutuhan spesifik. Mereka mengusulkan pendekatan bernama **WYSIWIB** (*What You See Is Where It Bugs*). Intinya, pengembang bisa mencari kesalahan dalam kode menggunakan bahasa yang sangat mirip dengan bahasa C biasa. Alat ini bekerja seperti mesin pencari, tetapi bukan mencari teks, melainkan mencari alur logika program (*control-flow*) yang salah. Dengan cara ini, pengembang bisa dengan cepat menyesuaikan pencarian untuk mengurangi laporan kesalahan palsu (*false positives*) dan menemukan ratusan potensi kerusakan pada sistem Linux.



**Bedah Abstrak Mendetail**
1. **"Eliminating OS bugs is essential to ensuring the reliability of infrastructures ranging from embedded systems to servers."**
   - *Maksud:* Menghapus kesalahan (bug) pada sistem operasi sangat penting untuk menjamin keamanan perangkat, mulai dari sistem kecil (embedded) hingga komputer server besar.
2. **"Several tools based on static analysis have been proposed for finding bugs in OS code."**
   - *Maksud:* Sudah ada beberapa alat berbasis analisis statis (mengecek kode tanpa menjalankan program) yang dibuat untuk menemukan bug di sistem operasi.
3. **"They have, however, emphasized scalability over usability, making it difficult to focus the tools on specific kinds of bugs and to relate the results to patterns in the source code."**
   - *Maksud:* Namun, alat-alat tersebut lebih fokus pada kecepatan menangani kode besar daripada kemudahan penggunaan, sehingga sulit bagi pengembang untuk mencari bug spesifik atau memahami hubungannya dengan pola kode asli.
4. **"We propose a declarative approach to bug finding in Linux OS code using a control-flow based program search engine."**
   - *Maksud:* Peneliti mengusulkan cara deklaratif (langsung menyatakan apa yang dicari) untuk menemukan bug di Linux menggunakan mesin pencari program yang berbasis alur logika (control-flow).
5. **"Our approach is WYSIWIB (What You See Is Where It Bugs), since the programmer expresses specifications for bug finding using a syntax close to that of ordinary C code."**
   - *Maksud:* Pendekatan ini disebut WYSIWIB karena pemrogram menuliskan kriteria pencarian bug menggunakan aturan penulisan yang sangat mirip dengan bahasa C sehari-hari.
6. **"The key advantage of our approach is that search specifications can be easily tailored, to eliminate false positives or catch more bugs."**
   - *Maksud:* Keuntungan utamanya adalah kriteria pencarian bisa diubah dengan mudah untuk membuang hasil salah atau menangkap lebih banyak bug yang tersembunyi.
7. **"We present three case studies that have allowed us to find hundreds of potential bugs."**
   - *Maksud:* Peneliti menunjukkan tiga contoh kasus di mana mereka berhasil menemukan ratusan potensi kerusakan pada Linux menggunakan alat ini.

**Baseline**
* **SLAM / SDV (Ball et al., 2006):** Digunakan sebagai baseline alat analisis statis mendalam untuk driver perangkat yang fokus pada verifikasi protokol formal.
* **Engler’s System Rules (Engler et al., 2000):** Digunakan sebagai baseline metode pengecekan aturan sistem menggunakan ekstensi kompiler yang ditulis oleh pemrogram.
* **PR-miner (Li et al., 2005):** Digunakan sebagai baseline teknik penambangan aturan pemrograman (*programming rules*) secara otomatis untuk mendeteksi pelanggaran pada kode besar.
* **Bugs as Deviant Behavior (Engler et al., 2001):** Digunakan sebagai baseline filosofis yang menganggap bug sebagai penyimpangan dari pola perilaku kode yang umum.

**Keyword**
Bug finding, Linux, Program search engine, Control-flow, Declarative approach, API protocols.

**Kelayakan untuk Riset "CODE SEARCH"**
**SANGAT LAYAK (Konteks Program Search).**
Paper ini sangat relevan jika riset "Code Search" Anda meluas ke bidang **Program Search** (mencari pola logika di dalam kode, bukan sekadar mencari file). WYSIWIB membuktikan bahwa teknik pencarian bisa digunakan sebagai alat diagnostik untuk keamanan perangkat lunak. Ini memperkaya riset Anda dengan argumen bahwa mesin pencari kode tidak hanya untuk membuat program baru (*reuse*), tetapi juga untuk membersihkan program dari kesalahan (*bug localization*).

**Perbedaan dengan Paper Sebelumnya**
1. **Jenis Kueri:** Berbeda dengan paper **SNIFF (2009)** yang kuerinya bahasa Inggris, WYSIWIB menggunakan kueri **berbasis sintaksis C** (kode mencari kode).
2. **Unit Pencarian:** Jika paper **Sourcerer (2009)** mencari dokumen atau file, WYSIWIB mencari **jalur eksekusi (control-flow path)** di dalam fungsi-fungsi Linux.
3. **Tujuan Utama:** Dibandingkan dengan **MAPO (2009)** yang memberikan rekomendasi pola API untuk produktivitas, WYSIWIB memberikan hasil pencarian berupa **pelanggaran protokol** untuk meningkatkan keandalan sistem.
